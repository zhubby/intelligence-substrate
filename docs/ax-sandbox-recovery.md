# AX 客体中断与人工核对

AX 控制器在创建外部资源前，先通过平台事务写入 `sandbox`。它绑定项目、目标、工作项、原执行与节点、批准版本、原租约摘要、命令摘要、后端配置及准确 Task/Workspace 名。准备记录已提交后，Worker 才能调用 AX apply。

## 状态与阻断

| 状态 | 含义 | 后续处理 |
|---|---|---|
| prepared | 已登记创建意图，尚无确定的清理回执；也可能根本没发出 apply | 原 Worker 报告清理结果，或负责人核对 |
| unresolved | 原 Worker 已报告清理不确定 | 负责人隔离原节点并核对 |
| stopped | 原 Worker 给出确定回执，或负责人记录原客体已停止 | 按工作项剩余配额及原规则继续 |

`stopped` 只表示客体清理状态；原命令仍可能非零失败，不能据此生成通过证据。Worker 成功回执要求未发出任何创建请求，或准确 Task 和 Workspace 删除均成功，且限定 atespace 的完整列表确认两者均不存在。查询失败、空白/畸形输出、作用域不符、残留同名对象、部分删除、超时均进入不确定状态。

同一执行有未停止客体时，不能上报成功、提交源码/制品或再次调用模型。同目标的过期、取消、失联、已停用节点或超过截止时间的未停止客体，阻止重试和新租约；换方案不能隐藏旧记录。有效并行执行可以继续，其他目标不受该客体影响。失败回执仍可保存诊断。

普通 Agent 的费用、活动时间、调用次数继续使用累计配额规则；固定命令等任务保留各自原规则。核对不会增加配额、重置尝试次数、恢复旧租约、采用旧工具输出或自动重放命令。

## 负责人操作

1. 在目标的“执行记录”查看“AX 客体待核对”，打开准确记录；该入口包含目标所有方案的未停止客体。
2. 对照原节点、准确资源名、后端配置/摘要和原执行日志，确定原 AX 控制面与 Substrate 实例。mtls-v1 记录同时显示两条固定 endpoint、服务名、公钥 pin、CA/客户端证书摘要，按[身份手册](ax-trusted-transport.md)核实原配置。摘要不是物理资源停止证明。历史 CLI 记录没有认证身份；变更 kubeconfig、AX_SERVER 或包装程序后必须核实原地址。
3. 从基础设施侧停止或隔离原 Worker，撤销其 AX/Kubernetes/路由权限，确认延迟请求不能继续创建资源。平台的“停用原执行节点”只撤销平台权限，不会杀死进程或撤销外部凭据。
4. 等待原租约失效。仅租约过期、平台重启或 Worker 进程死亡，都不足以证明远端任务已停止。
5. 在原后端核实准确 Task、Workspace 及相关 Actor；根据企业流程停止残留客体，并检查模板、快照、存储和未完成操作。不要删除不属于本次记录的对象。CLI 列表无对象只证明该控制面的登记状态，不能独立证明物理执行与存储回收。
6. 记录核对依据并勾选外部隔离/停止确认，再点“确认已停止”。后端复核人工负责人权限、原节点已停用及原租约已失效；要求准确 name、backendDigest 和稳定幂等键。
7. 再按已有流程重试工作项。新执行使用新租约和新客体，仍需构建、独立验证与发布审批。

负责人核对接口记录的是操作员决定，不执行外部删除，也不验证操作员陈述。基础设施侧无法确认时，应保持阻塞。节点/资源尚未停止时不得以“继续执行”为由填写已停止。

## 控制器接口

全部命令通过认证的 `POST /api/v1/commands/{command}` 执行。人工会话变更需要 CSRF。普通 Agent 无人工核对权限；人工核对未加入 Agent 的 MCP 通用命令白名单。

- `sandboxes.prepare`：输入 `runId, leaseToken, key, backend, command`。backend 包含 `context, namespace, atespace, image`，可增加严格的 `transport:{version:"mtls-v1",control,guest}` 公开身份；其他字段拒绝，身份结构见[身份手册](ax-trusted-transport.md)。image 固定为 SHA256 摘要，argv 与固定任务/受保护质量管线一致。当前 Linux Worker 的项目、角色、能力、租约、截止时间与批准方案均须有效。新响应临时带 `data.replayed=false`；同键同输入返回同记录并带 true，Worker 必须拒绝再次执行。重复准备也复核当前权限/能力/方案。
- `sandboxes.finish`：输入 `id, leaseToken, name, backendDigest, stopped, observation`。仅原 Worker 及原租约摘要可提交，允许在租约到期或任务取消后报清理结果；已停用/撤权凭据仍被拒绝。回执不可改写，同输入可重试；先报 unresolved 后不能自行改成 stopped，需人工核对。
- `sandboxes.reconcile`：输入 `id, key, name, backendDigest, observation`。仅当前人工负责人；原节点必须停用，原租约必须无效。准确同键同内容可重试，不同内容冲突。操作与幂等历史持久化并入审计链。

准备成功但响应丢失时，保留记录等待处理；不能换键再次 apply。清理成功但回执响应丢失时，也不能把未经确认的成功输出当作已交付。备份保留客体及幂等/审计状态，恢复不带原会话/节点令牌，重新授权后仍须处理未停止客体。

## 验证与边界

源码中的 Go 测试覆盖 SQLite/PostgreSQL 事务、双连接竞争、回滚、备份恢复、准确回执、权限、方案变化、并行工作及失败阻断。HTTP Worker 测试启动实际子 CLI 进程并执行固定本地命令；该 CLI 是明确的本地契约替身。浏览器中的远端核对依据也为合成数据。

本轮还以真实固定版本 AX CLI 对本地 gRPC 提供方验证删除/列表格式，包含存在、缺失、拒绝、不可读及错误作用域；不能把它当作真实集群故障演练。此前实际 AX 互通条件仍见 [AX 执行](ax-execution.md)。本次没有变更真实 AX 集群。

真实 Worker SIGKILL、控制面 SIGKILL/重启及原 90 秒租约实际等待，验证了持久意图在进程死亡后继续阻断替代执行。独立 CLI 进程在原控制器死亡后仍存活，须由实验操作员外部停止，再停用节点并核对。新 Worker 随后执行新的准确命令。实验使用本地替身，不证明 Substrate Actor 在真实宿主丢失后的迁移/停止、企业权限隔离、自动会话恢复或存储 GC。

后续 mtls-v1 增量已实现两端明确身份的受控连接，并以本地 TLS/协议提供方验证；真实企业网关授权、可撤销且最小授权的节点凭据、跨节点外部 fencing，以及真实 Actor/模板/快照核查仍需验收。Apple/Windows 原生构建、企业签名、真机、真实商店与生产发布及两应用完整正式交付继续独立验收，完整 P3 保持开放。
