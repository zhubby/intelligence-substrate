# Agent 源码修改范围

代码工作项可以声明允许修改的文件和目录。负责人在交付方案和批准对话框审查范围，批准后执行；工作项详情保留相同范围。扩大范围需要提交并批准新方案。

```json
{
  "id": "backend-priority",
  "title": "实现后端反馈优先级",
  "kind": "code",
  "role": "developer",
  "runtime": "linux",
  "writePaths": ["backend/", "app/[id]/page.tsx"]
}
```

`writePaths` 是任务字段，随 `plans.propose` 或模型生成的任务提案提交。它不属于源码快照请求的元数据。模型只能提出范围，人工批准的方案才授权执行。

## 路径规则

- 只有 `kind=code` 可以声明。显式数组需要1–128项，每项为字符串；`null`、空数组和空字符串均无效。
- 文件精确匹配；目录以 `/` 结尾，包含其下全部层级的文件。`backend/` 不允许修改 `backend-extra/file.go`，也不允许将 `backend` 目录替换为同名普通文件。
- 不解释通配符，`app/[id]/page.tsx` 是字面路径，不匹配 `app/i/page.tsx`。
- 使用规范相对路径，拒绝绝对路径、穿越、反斜杠、Git元数据、控制字符和跨平台保留名称。重复项和大小写/Unicode规范化歧义也被拒绝；规范化后按路径排序保存。
- 未声明时保持旧任务的全仓库范围。工作台明确显示“全仓库（未限定路径）”。此兼容规则不表示推荐宽权限；对职责已知的开发任务应指定范围。

范围限制的是最终代码产物。它不会限制读取文件，也不替代原生、容器或AX执行驱动的进程、网络与宿主隔离。已有项目权限、密钥、质量门槛与发布审批继续独立生效。

## 强制检查与审计

Worker 在直接 `write`、`delete` 和 `take_input` 操作前检查范围，向 Agent 返回拒绝观察。Agent 可以据此纠正操作或请求重新规划。

控制面对真实Git树再次检查。完整快照与旧文本提交均比较最终树和领取时绑定的基础提交，检查新增、修改、删除、二进制与执行权限；重命名按删除和新增检查两端。仅未改变的范围外文件可以保留。检查发生在创建提交对象、prepared记录、change和候选分支之前。

越界返回HTTP409，错误包含 `writePaths` 与最多8个路径提示，并保留拒绝审计。完整快照只有在第一事务、尚未创建候选的范围拒绝才返回专用 `source_write_scope_rejected`；旧文本入口、prepared第二事务与人工恢复保持普通冲突。输入格式错误返回422。修正后的快照可在原有效租约内重新提交；拒绝不会消费该请求的成功幂等结果。分支、需求或方案已经变化时，仍按原冲突处理流程执行。

普通代码Agent收到该专用拒绝后，可以使用 `restore_base` 恢复绑定基线的一个准确文件或撤销原本不存在的普通文件，再次完成提交。它不能选择其他版本或任意内容，也不能递归删除目录；步骤、预算、原源码和范围保持累计。等待与换节点可以保存已纠正草稿，未知结果继续停止核对。详见[拒绝后的纠正手册](source-write-correction.md)。

任意 `run` 命令仍可能在其执行环境中写文件。越界结果会在最终提交时被拒绝，不能成为成功源码或下游构建输入。Worker在中断保存机制中保留私有失败源码及原绑定摘要；`local_only/incomplete` 不表示候选已被采用，也不产生质量或发布证据。

## 集成和恢复

集成工作项的范围覆盖相对其绑定基础提交的**全部最终变更**，包括其他父输入带入的路径。应先审查选定输入，再授权足够范围；不能用集成任务绕过各路径的授权。冲突决定、原始父历史和独立质量验证继续保留。

范围随新任务的源码选择摘要和 `sourceBinding` 冻结。历史任务未声明范围时沿用原摘要算法。协作等待和持久进度的配方摘要覆盖完整任务；新范围自然进入原有恢复校验。

拆分子项继承原范围，拆分/重排请求不能携带范围覆盖。重试和等待恢复沿用原绑定。完成prepared快照及负责人人工确认候选时，重新核对真实树和原范围；批准新范围不能追认旧执行。

## 验证与后续验收

回归包含真实Git/SQL的内容、删除、二进制、模式、目录前缀、重命名与字面方括号路径，旧文本入口，冻结字段损坏，拆分/重排/重试/等待/进度，实际finalize故障与人工恢复，集成带入路径，以及PostgreSQL跨连接重放。

固定模型动作经真实认证HTTP驱动Worker，验证直接拒绝后合法纠正，以及命令越界后的私有保存和下游阻塞。它是平台边界验收，不证明真实模型能正确开发。真实7B试验的失败继续保留在[054记录](local-model-multiplatform.md)。

浏览器测试使用隔离实例，覆盖桌面和390px视口的输入、方案、批准对话框、任务详情及缺省范围展示：

```sh
rtk proxy python3 scripts/verify-workbench.py --suite source-write-scope --suite plan-generation
```

本轮实际回归数量与独立读回以[验证记录](validation.md)为准。原18080预览保持既有版本。完整五端业务研发、Apple/Windows原生与真机、企业签名和正式渠道的验收仍见[产品验收清单](product-acceptance.md)。
