# 方案生成、请求记录与中断处理

从当前已批准需求生成待审交付方案。模型返回方案不会启动执行；人类架构负责人或项目负责人仍需单独批准。原有[人工编制](api.md)与Agent提交方案入口保留。

## 使用工作台

在“目标与需求 → 交付方案”选择“生成方案”，核对目标、需求版本和模型预算说明后确认。对话框固定本次目标、版本和请求键；发生错误后在同一对话框重试，沿用同一请求，避免重复模型调用。

“方案生成记录”显示处理中/待核对、生成未完成或已生成，保留请求人、需求版本、时间、方案及费用关联。费用仍是按配置估算或经人工核对的金额，不是提供方账单。没有关联费用记录不代表已证明零费用。

失败后可转人工编制。重新打开生成对话框代表一次新请求；先检查旧请求和费用，再决定是否重新发起。达到预算、上下文、速率或调用次数限制时，沿用原模型网关的拒绝/等待规则。

## API与Agent

```json
{
  "goalId": "goal_example",
  "expectedRequirementRevision": 3,
  "key": "client-owned-planning-attempt-001"
}
```

发送到`POST /api/v1/plans/generate`。三个字段必填，拒绝其他字段；key为1–160字节文本，版本须为当前正整数。此前仅有goalId的调用方需要升级，服务不会为它默默补随机键。

人和项目Agent具有product、architect或developer权限时可以发起；owner沿用原项目权限继承。脱离执行租约的Worker不得调用此入口。Cookie请求要求Origin/CSRF；Agent使用项目凭据。当前身份、凭据及成员权限在创建、模型准入及结果提交事务内重新检查。方案批准仍只允许人类architect/owner。

成功返回`plan`资源，status=proposed，带generationId、inputDigest、chargeId及origin=model。通过授权workspace读取`plan_generation`和`charge`；MCP保留plans.propose与授权资源读取，不暴露生命周期完成/失败命令。公开Chat字段无法指定内部请求或绕过需求批准。

## 请求与费用语义

| 情况 | 返回与持久状态 | 再次提交同键 |
|---|---|---|
| 完成并成功写入待审方案 | succeeded；方案/费用/输入摘要/审计绑定 | 返回原方案的当前状态，可能已active或stale |
| 同键正在处理 | running | 409，不再调用模型 |
| 网络、格式、用量、权限或上下文失败 | failed；保留已发生费用与原因码 | 409，不再调用模型 |
| 进程被终止 | 可留下running与reserved | 重启后409，不再调用模型 |
| 同键更换版本或请求内容 | 不覆盖原请求 | 409，幂等冲突 |
| 开始前版本/角色无效 | 不创建请求或费用 | 更正输入后使用明确的新请求 |

幂等范围为目标和请求主体，最多200份请求/目标。新键不规避模型总调用数或预算限制。每份可信意图只允许一条模型费用预留。开始/完成审计失败回滚相应业务写入；已发生的模型费用不因方案未保存而消失。

只有完整输出且费用已结算、outcome=completed时，控制面才解析summary、risk和tasks，使用原DAG/角色/系统/源码/制品/命令规则验证。模型不得附带批准、证据、目标替换或控制面内部字段。方案来源纳入其批准绑定。

## 上下文与迟到结果

网络前在事务中保存准确输入及SHA256：需求版本、业务说明、人审来源、验收标准、渠道、预算、来源、冻结人工答复、基线批准、活动方案、知识版本、仓库默认头及启用节点能力。

模型准入与提交前重新计算。需求改版、重复批准、活动方案变更、知识更新、仓库头变化、节点禁用/能力变化或输入摘要不符，均拒绝旧结果。模型本次费用、心跳时间、任务进度及其他项目资料不参与摘要，不会使请求自行过期。输入是业务数据，不是权限来源。

## 崩溃和恢复

先查看请求、关联费用、审计和提供方记录。不得把running改成“没有发生”或把未知费用直接归零。按[模型手册](live-model.md)核对费用；费用核对不授权重发旧请求。需要重新规划时，由有权主体明确创建新请求，旧记录继续保留。

本实现不查询或恢复提供方的旧结果，不恢复模型会话或工具步骤，也不提供管理员伪造完成按钮。数据库备份包含请求、原始输入摘要、方案来源和幂等历史；恢复不自动重放模型请求。按[运行手册](operations.md)执行备份恢复。

## 验收边界

本增量使用本机确定性模型验证SQL/HTTP、权限、并发、上下文、故障、浏览器和中断恢复契约。它不证明真实模型规划质量、自主质量调度或完整P3正式交付。原生构建、真机、签名、渠道账户、正式上架及企业生产验收仍需独立证据。具体检查结果记入[验证记录](validation.md)。
