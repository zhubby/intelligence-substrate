# Agent 持久进度与中断恢复

普通 Agent 在每次工具操作前登记意图，完成后保存观察和工作区。节点或控制面中断后，可用节点从最后确认的进度继续推理；结果不明的操作需要负责人先核对。适用于无固定 `command` 的 analysis/code/design 工作项，排除蓝图初始化。固定命令、签名、发布保持各自的执行和恢复协议。

## 正常执行与恢复

领取的 `run.data.agentProgressVersion:1` 表示启用此契约。可信 Worker 按以下顺序工作：

1. 按原累计配额调用模型，得到一个公开工具操作。
2. `agent_steps.prepare` 事务保存准确操作、序号、摘要、原执行/节点、需求/方案、工作配方、源码和上一确认步骤。相同请求返回同一记录，内容不同的重放被拒绝。
3. 收到准确确认后执行一次工具。读取、文件变更、命令、集成决定、协作消息和受控计划调整均登记意图。
4. code/design 将完整选中源码保存为私有归档，包含二进制、可执行模式和删除；analysis 仅保存观察。`agent_steps.complete` 将准确观察和归档原子绑定到步骤，并推进工作项的 `agentProgressId`。
5. 最终源码提交、设计提案和工作项成功完成仍走原有协议，随后进入原独立评审/质量流程。

替换执行的 `agentResume` 绑定最后确认步骤和准确归档，先核对当前需求、方案、配方、源码目标、字节和权限，再恢复文件。整棵临时源码树被替换，避免已经删除的文件重新出现；集成工作恢复已确认的冲突决定。失败执行之后未确认的修改或决定不能混入。

模型使用全新会话，读取有界的公开操作类型、摘要和实际观察，均标为不可信数据。提供方隐藏推理、旧对话、运行进程、连接、环境、内存和忽略的缓存不进入恢复状态。持久协作收件箱独立恢复。没有已确认普通进度时，按原显式等待检查点或原固定源码启动。

`finish`、`blocked`、`wait` 不登记普通工具意图。成功的显式协作等待保存原等待记录，并清空普通进度指针；回复后的文件和冲突决定由等待检查点提供，后续普通步骤再建立新的进度链。普通步骤的确认不会将检查点登记为源码提交、设计、质量证据或发布批准。

`restore_base {path}` 属于普通非终结工具：先保存准确意图，再从代码任务的绑定基线恢复一个文件或其不存在状态，最后确认观察及文件归档。它不接受自选版本或内容。`finish` 只有收到 `source_write_scope_rejected` 才在原有累计 24 步内继续纠正，并允许后续保存进度或显式等待；其他提交错误继续停止核对。历史提交标记仍阻止受控停止时自动再次提交。换节点使用原绑定和累计额度，详情见[源码纠正](source-write-correction.md)。

## 结果不明时的负责人操作

在目标的“执行记录”查看“Agent 操作待核对”。详情展示原执行、节点、操作摘要、公开操作、保存状态和核对依据。

存在 prepared 步骤时，该工作项不能再推理、显式等待、成功完成或重试。原执行失效或节点停用后，同一目标跨方案的新执行也会阻塞；仍有效的并行工作可以按原批准范围继续。修改方案不能隐藏旧操作。

负责人依次处理：

1. 独立检查并停止原工具进程/客体，核对外部系统和真实副作用。租约到期和平台“停用节点”均不证明物理进程已经停止。
2. 停用原执行节点，等待原执行租约 inactive。界面在原租约仍有效时禁止确认；服务端重新检查准确状态和当前负责人权限。
3. 对照准确 `actionDigest`，填写核对依据并明确确认已检查进程与外部副作用，记录 `agent_steps.reconcile`。该操作将未明步骤标为 abandoned，保留原操作、节点、时间和核对人。
4. 单独重试原工作项。新执行恢复最后确认进度和剩余配额；没有确认进度时使用原输入。未明步骤的工作区修改不会采用，工具不会由恢复协议自动重播。

该决定由当前人类项目负责人作出，开发 Agent 和 Worker 不能代为确认。核对意图有独立幂等 key；不同内容不能覆盖原决定。界面记录决定后不会自动重试。模型费用、源码提交及 AX 客体若也有未明结果，仍须通过各自的核对门槛。

此流程不能撤销已发生的外部影响，也不承诺外部 exactly-once。负责人需要在核对依据中解释保留、补偿或人工接管的结果；若原进程或外部状态无法确认，应继续保持阻塞。

## API 与限制

| 操作 | 契约 |
|---|---|
| `agent_steps.prepare` | `runId`、`leaseToken`、整数 `step`、公开 `action` 和准确 `source:{repositoryId,commit}`；拒绝未知字段 |
| `POST /api/v1/agent-steps/{stepId}/checkpoint` | `application/x-tar`、唯一 `X-IS-Lease`；前后事务均重新鉴权和检查当前绑定 |
| `agent_steps.complete` | `id`、`runId`、`leaseToken`、实际 `observation`、准确 `checkpointId`；analysis 的检查点为空 |
| `GET /api/v1/runs/{runId}/agent-checkpoint` | 仅准确活动恢复执行可下载；唯一 `X-IS-Lease`、无查询参数、no-store/nosniff |
| `agent_steps.reconcile` | `id`、`key`、准确 `actionDigest`、`externalReconciled:true`、`reason`；当前人类负责人、原节点 disabled、原租约 inactive |

租约只放在请求体或专用头，不能放 URL。原认证凭据、节点、范围、源码目标或预算在上传期间改变，提交事务会拒绝保存；权限拒绝写入 `denied:agent.checkpoint` 审计。成功上传使用 `agent.checkpoint`，与显式等待的 `workspace.checkpoint` 区分。

单个操作 JSON 不超过 64 KB，观察不超过 16 KB。恢复每条观察最多 8 KB，总 trace 最多 32 KB；历史完整记录仍留在控制面。任务继续使用原累计预算、活动时间和 24 次模型请求上限；费用未知时不能换节点重置配额。模型预算恰好归零后，最后已准入模型产生的工具动作仍可执行并确认保存；新增推理、领取和显式等待继续要求正的剩余预算，超支或时间用尽会拒绝。准确限制见[累计配额手册](agent-allowance.md)。

源码仍受 64 MiB（含 tar framing）及 20,000 项上限约束，拒绝路径逃逸、符号链接、特殊文件和控制器制品目录；设计检查点只能改变原约束下的非可执行 HTML。本地归档位于可信 `stateDir/agent_{stepId}.tar`，上传结果不明时保留供核对。私有归档可能含业务源码和工具输出，应按项目数据保护与保留策略管理。

逻辑备份包含 `agent_step`、`agent_checkpoint`、准确检查点字节、幂等记录和审计；恢复撤销原凭据。备份恢复不会消除 prepared 屏障。逐步骤保存完整归档会增加 I/O 和存储，本版未增加归档 GC、增量快照或容量收益承诺。

## 与其他恢复机制的关系

- [显式协作等待](workspace-waits.md)处理主动等待准确回复并释放资源，普通进度处理已确认工具后的非预期中断。
- [受控停止源码](source-recovery.md)仍服务于没有未明普通操作的受控错误返回；存在未明操作时不以该回退采用不确定源码。
- [源码提交恢复](source-snapshots.md)、[模型费用](agent-allowance.md)及[AX 客体清理](ax-sandbox-recovery.md)保持独立。普通进度不替代它们的最终确认。
- [独立质量](quality-scheduling.md)、签名、发布批准和渠道验证始终检查准确后继提交及制品。

本地验证采用确定性模型提供方，命令、控制面/Worker 中断、90 秒真实租约等待、替换节点、文件恢复和备份读取是真实执行；不能据此认定真实模型协作质量、物理宿主迁移、多端业务验收或完整 P3 正式交付通过。
