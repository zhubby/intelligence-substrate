# Agent 重试与替代节点的累计配额

金额沿用现有模型费用口径，不新增基础设施自动计量。一个已批准的 Agent 工作项只有一份预算、活动执行时间和模型调用额度。普通失败、租约过期、协作等待及更换节点，都使用同一份剩余额度。

适用无固定 command 的 analysis/code/design；蓝图初始化、固定命令、独立质量、签名和发布沿用各自现有规则。此次没有扩大任务、模型或发布权限。

## 领取与调用

`tasks.retry` 在实际重试前核对历史配额；`tasks.claim` 在创建租约前核对；`model/chat` 在创建费用预留的同一 SQL 事务再次核对。模型请求必须属于当前需求基线、活动批准方案、匹配配方和节点能力、有效租约及 deadline。并发请求共同消耗已持久化的调用额度。

例如，原工作项批准 100 分、600 秒，第一执行已消费 40 分、120 秒、7 次调用。替代执行最多预留 60 分，使用 480 秒和 17 次调用。等待回复的时间不占活动执行时间；失联执行计算到原租约截止和 deadline 中较早者。节点恢复不会重新发放 100 分或 600 秒。

每工作项累计最多 24 个已预留模型请求。无效输出、主动 blocked、传输失败、零费用请求和事后核对为零费用，都已经消耗一次调用。被入口拒绝、尚未预留的请求不计入。已有协作等待的步骤下界会继续保留，不能靠旧协议或失败重试丢弃。

新 run 的 `data.agentAllowance` 是领取时快照：

```json
{
  "usedModelCalls": 7,
  "spentCents": 40,
  "activeSeconds": 120,
  "remainingCents": 60,
  "remainingSeconds": 480
}
```

`reservedCents` 和 `deadline` 使用剩余金额与时间。快照不会随着后续费用核对自动改写；实际推理仍读取事务中的历史记录，并同时受当前 run 原预留上限约束。原 task 的批准金额、时间及配方保持不变。

## 结果未明与人工核对

关联任务的任意费用为 `reserved` 或 `uncertain` 时，不继续创建执行或模型请求。节点可能已经调用了提供方，重启不能证明请求未发生。平台保留原记录，工作项显示费用待核对原因。

项目负责人按实际提供方记录调用原 `charges.reconcile`，输入费用 ID、整数 `chargedCents` 和非空依据。费用核对不会恢复旧凭据、旧租约、模型会话或调用次数，也不自动启动任务。核对完成且原预算、时间和尝试次数仍有余额时，可人工 `tasks.retry`，再由可用节点领取。

累计预算、活动时间、24 次调用或原重试次数任一用尽，都需要新方案；通用 retry 不扩额。事后上调旧执行费用可能使已经领取的 run 再次停止推理。新费用与旧执行仍可通过原 charge/run 追溯，不能把入口快照当作当前余额。

## 文件与协作边界

替代节点继续读取当前工作项的持久收件。显式协作等待仍可恢复最后一次已确认的准确文件检查点；普通中断按[Agent 持久进度](agent-progress.md)恢复最后确认的进度，没有确认进度时使用原批准输入。新执行不恢复旧模型会话、进程或工具会话，也不自动重放原命令。未确认操作、开发源码和费用待核对时，各自恢复屏障继续适用。

本实现以可信控制面和可信 Worker 为边界，不能证明一个失联或恶意节点停止了外部副作用，也不能消除人工错误费用核对。正式模型业务质量、AX 主机迁移、企业签名、设备和正式渠道交付仍需单独验收。

## 验证方式

真实 SQLite/PostgreSQL、HTTP 与 Worker 循环验证配额继承、同一任务收件、费用核对、单次租约/最后一次模型调用竞争、回滚和便携备份恢复。确定性本地模型提供方只用于验证协议和状态，不是实际大模型决策质量证据。实际进程强制终止实验另行记录，只有成功结果才计入[验收记录](validation.md)。

定向命令：

```sh
rtk proxy go test -race -count=1 -timeout=20m ./internal/platform ./internal/integrations ./internal/worker -run 'Test(Agent|PostgresAgent|WorkerUsesRemainingModelCalls|WorkerReplacementSharesActualModelAllowance)'
```

PostgreSQL 测试须配置隔离的 `IS_TEST_POSTGRES_URL`；未配置的 skip 不能计为数据库验收。部署升级不会修改历史任务或费用，历史已经耗尽/未核对的工作项会按现有记录阻塞，应由负责人核对或重新规划。
