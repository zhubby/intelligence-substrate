# 真实模型接入与研发验收

模型运行在可信控制面，通过兼容 Chat Completions 的适配器调用。开发容器只接收源码和工具命令，不接收模型密钥、平台令牌或数据库凭据。真实模型可生成待批准方案，也可在已批准工作项中逐步操作隔离工作区；完成代码生成不等于质量通过或正式发布。

## 配置

配置 `IS_MODEL_BASE_URL`、`IS_MODEL_NAME`、`IS_MODEL_API_KEY_FILE` 和输入/输出每百万 token 的美元估价。外部调用还要求项目负责人启用 `allowExternalModels`；内网模型显式设置 `IS_MODEL_EXTERNAL=false`。默认仅允许 HTTPS，不跟随跳转。

`IS_MODEL_DEFAULT_MAX_TOKENS` 是规划和内置开发 Agent 的默认输出预算，默认 4096，允许整数 1–8192。推理型模型的思考也占用该上限，过小会造成截断。显式 API 请求的 `max_tokens` 同样必须为这个范围内的整数；配置默认值不能突破目标或工作项费用预算。

`IS_MODEL_MIN_INTERVAL_SECONDS` 默认 0，允许 0–300 的有限数值。同一数据库按提供方地址和模型保存下一次允许调用时间；多个控制面实例、重开数据库后仍遵守间隔。等待不占用 SQL 事务，也不生成费用预留，取消等待不会访问提供方。入场时重新检查项目策略、批准基线、执行租约和预算。这个间隔不保证满足提供方所有 RPM/TPM 限制，也不在不同数据库之间共享；不自动重放已经发送的请求。

`IS_MODEL_OPTIONS_JSON` 允许管理员设置提供方明确支持的 `thinking.type`（enabled/disabled）或 `reasoning_effort`（low/medium/high/max），最多 2 KiB。其他键、非法结构和覆盖模型/消息/stream/max_tokens 均被拒绝。选项写入费用来源记录；不能由任务或模型临时修改。例如 kimi-k2.6 官方支持 `{"thinking":{"type":"disabled"}}`，而始终思考的模型不能套用该配置。

修改配置后由运维部署新的控制面。已有旧进程不会自动获得新配置；部署或现场验收应使用明确的二进制和环境，不覆盖其他运行实例。

## 状态与费用

每次调用先原子检查权限、预算与入场条件，再创建 `charge` 预留费用。上下文限 128 KB，提供方响应限 2 MiB。只有完整且可计量的响应才能进入后续动作：

| 结果 | 执行处理 | 费用处理 |
|---|---|---|
| 完整内容、有效用量 | 继续解析受控动作或待批准方案 | 按配置费率和实际 token 估算结算 |
| 截断、拒绝、过滤、空内容 | 阻止动作 | 用量有效时照实结算 |
| 缺失/异常/超上界用量 | 阻止动作 | `uncertain`，保留预留上界 |
| 网络错误、HTTP 429/5xx、响应过大 | 阻止动作 | `uncertain`，待负责人核对 |
| 排队时取消、策略撤销、失去租约、超预算 | 不发送新请求 | 不创建新费用 |

记录包括提供方地址、协议、响应 ID、实际模型名称、HTTP 状态、完成结果、输入/输出 token、历史配置费率和 `pricingBasis=configured-estimate`。这些金额是配置估计，不能称为提供方账单或交付总成本。真实外部结果不明时不能自动退款为零；负责人使用 `charges.reconcile` 记录核对依据，chargedCents 必须是显式整数美分。[交付成本](delivery-costs.md)汇总模型估算、人工核对及外部登记，将预留/未知和缺失类别另列，保留不完整口径。

规划上下文包含当前项目的需求、验收标准、目标、仓库、已注册节点、版本化知识及准确批准的澄清问答，不包含凭据或其他项目资料。开发 Worker 读取相同的问答快照并验证摘要；答复作为业务数据，不授予权限。Agent 的 approvedWork 仅包含当前执行所属方案的工作项，排除已被替代方案的任务。[方案生成](plan-generation.md)在网络前持久化精确上下文、请求键和来源，准入/完成均事务复核；同需求版本内的知识、仓库头、节点能力或活动方案变化也拒绝迟到结果。成功回放原方案，处理中/失败/进程中断同键409，不重复调用；已实际发生用量保留，planRequestId关联费用。仅生成待审方案，不激活执行。

[需求澄清](requirement-clarification.md)与[需求稿](requirement-drafts.md)提供受控的草稿模型入口，由人类产品负责人发起，先持久化意图再使用原模型策略与预算。模型只形成待确认问题或待人审需求；同请求成功回放原结果，运行中或失败返回409，不重发。进程中断保留意图及预留费用，需人工核对；普通Chat不能通过公开字段绕过基线批准。本机模型样本只验证契约，不证明真实模型的需求覆盖质量。

Agent 保留提供方返回的 `reasoning_content` 续接字段，以支持需要该字段的多轮兼容模型。该字段只用于当前受预算约束的模型上下文，不作为工具动作或面向用户的执行日志。模型每次返回的动作仍经过源码路径、租约、任务种类、权限及独立质量边界检查。

`approvedWork` 是当前方案的协作索引，提供 task ID、logicalId、标题、状态、依赖、角色、系统、仓库及预算。待办工作保留指令和固定命令，供拆分/重排时理解范围；已分配或已完成工作不再重复传入完整指令、源码绑定等执行元数据。当前工作项的完整说明及输入绑定仍在 `task` 中。这减少每轮上下文和保守费用预留，不压缩实际协作消息、当前指令或质量门槛。

## 有界的现场验收

`scripts/verify-live-model.go` 使用独立 SQLite、真实认证 HTTP、明确预算、实际模型调用、准确源码快照、容器构建及受保护的业务 QA。`scripts/live-model-qa.py` 位于生成仓库之外，独立执行准确制品的 HTTP、输入校验、并发、取消授权和重启持久性测试。

验收要求管理员明确提供固定 digest 的 Node/Python 工具镜像配置。开发容器无外网、根目录只读、非 root、无能力集，只允许工作区写入。示例命令不会创建商店发布或使用生产签名：

```sh
rtk proxy go run scripts/verify-live-model.go \
  -state work/new-private-model-feedback \
  -config /absolute/path/to/operator-worker.json \
  -mode feedback
```

该命令会实际调用付费提供方；先按部署手册配置模型、明确预算和项目策略。验收的批准身份是本地合成负责人，不能代替企业真实需求批准。

`-resume` 只在该工具原失败验收中，重试当前批准方案的阻塞任务，保留原需求、源码、费用和重试上限。普通 Agent 现按[持久进度与中断恢复](agent-progress.md)恢复已确认文件及公开工具观察，未确认操作必须先核对；新执行使用全新模型会话。达到重试上限后使用 `-replan` 在同一目标及预算内生成待审的新后端→界面→构建方案，由验收负责人检查后批准；原任务、执行和不确定费用保留，不修改其失败状态。

以下现场记录反映当时的能力与实际结果；新增持久进度不会追溯恢复旧执行已经丢失的临时文件，也没有重新运行这些付费验收。

两个业务变体使用无第三方依赖的 Node Web/API，分别验证反馈和预约，不替代既有 Flutter/Go 多端蓝图。只有实际生成、构建、独立 QA、真实浏览器都成功后，才能分别记为这些环节通过。自动化 CI 证据仍不能单独放行浏览器门槛。

### 真实浏览器质量流水线

成功生成制品后，可在同一验收数据库运行 `-browser scripts/verify-live-model-browser.py -browser-docker-host unix:///absolute/local/docker.sock`，并用 `-browser-executable` 指定实际已安装的 Chrome。此路径显式注册仅承担质量工作的 native 节点，执行管理员提供的受保护脚本；生成仓库不能替换脚本。它会启动本轮私有浏览器会话及真实应用容器，并在结束后停止它们，不重启已有预览。

应用使用固定 digest 的工具镜像、非 root、只读根目录、无能力集、无网络、独立状态及资源限制。宿主 loopback 网关通过 `docker exec` 转发到容器内真实 HTTP；POST 额外延迟 350ms 以验证等待期间的重复点击，响应来自实际应用，未替换 API。脚本执行桌面/390px 视口、实际表单、冲突/取消或脚本普通文本、断网恢复和重启场景，保存原制品摘要、请求状态、结果及截图。它是本地浏览器验收，不是外部发布、设备或生产验收。

`-repair-browser` 允许执行一次平台创建的受预算修复，随后使用原保护策略重建和复测。`-retry-browser-repair defect_...` 仅用于明确重试原阻塞修复，保留原额度与次数；保护脚本变化会拒绝此重试。失败和截断均保留，不能靠提高总预算、清零费用或替换产物制造通过。

预约验收另有显式 `-owner-browser-replan defect_...`，只在原自动修复达到上限时，由合成本地验收负责人批准固定原源码的“页面修复→重建”替代方案，在原目标剩余额度内分配执行预算。这是人工重新规划，原阻塞缺陷及两次失败仍保留，不记作自动修复完成。模型写入新源码后，新制品分别通过真实浏览器和完整独立 API 策略，才可创建待批准候选；该工具不批准或发布候选。

反馈独立 API 失败可使用显式 `-owner-quality-replan defect_...`：先实际执行原自动修复并确认预算停止，再由本地验收负责人批准后端修复/重建的模型替代方案。现场该方案仍在提交前遇到预算门槛，临时文件没有持久快照，不能使用源码核对接口冒称恢复。

`-owner-command-replan defect_...` 仅用于上述原反馈缺陷和当前替代方案的真实预算停止。负责人批准固定命令，将原准确源码中的 `path.join(process.cwd(), STATE_FILE)` 单表达式替换为 `path.resolve(STATE_FILE)`；通过平台正常 code 提交和 build，不直接改制品。该阶段不调用模型，保留全部历史和原总预算，报告明确 `manualSourceTakeover=true`、`finalRepairUsedModel=false`、`takeoverModelCalls=0`。完整原 API 策略通过后仍先验证浏览器门槛拒绝，真实浏览器通过才创建候选。这是人工工程接管，不能记为模型自主修复或原缺陷自动关闭。

## 本轮边界

2026-11-06 已通过真实模型的受治理 JSON 生成与两个业务的应用源码输出。预约首份 UI 的数字/字符串时段 ID 不一致被真实浏览器识别，自动修复先遇到保守预算门槛、后遇输出截断；最终经上述人工重新规划得到模型生成的新 UI，再通过浏览器/API 并创建待批准候选。后端字节未改变，原缺陷未伪造关闭。

反馈的初始模型制品因绝对状态路径错误而未通过独立 API；基础失败报告保持原样。模型修复未能在预算内提交后，使用上述人工固定命令修复，最终页面字节不变，后端只改变已说明的表达式。新制品通过原 API 策略及真实 Chrome：真实表单、防重复、脚本普通文本、断网输入保留/恢复、容器重启后数据保留、1440/390px、键盘和未捕获错误检查，形成待批准候选。原缺陷仍为 blocked，两个业务均不算完全自主修复成功。

最终估价累计：预约 345/500 美分（settled 294，uncertain 51）；反馈 430/500 美分（settled 179，uncertain 251）。两项目均未批准、部署或发布；上述不确定费用仍待有依据的核对，没有追加总预算或退款为零。最新完整产品回归为 214 个顶层测试、493 项含子场景与 21 个程序跨三平台编译；验收 CLI 另行编译并实际运行。完整记录见 [验证矩阵](validation.md)。

较早的另一个本机凭据返回 401，不代表所有凭据都不可用；密钥值没有写入文档或交付包。Moonshot `kimi-k2.7-code` 已出现真实 429、500 及思考占满输出预算的失败，另一个模型的开发请求也出现 500，相关记录保留。成功业务阶段使用 `kimi-k2.6` 和提供方支持的关闭思考选项；1024 的修复输出上限造成的实际截断也按 token 结算并拒绝执行，随后人工替代方案使用 4096。

现场采用输入 10 USD/M、输出 50 USD/M 的显式保守估价。提供方[官方价格页](https://platform.moonshot.cn/docs/pricing/chat)使用人民币，不能把本次美元配置当作准确汇率换算后的账单。[思考模型文档](https://platform.moonshot.cn/docs/guide/use-thinking-models)说明推理 token 计入输出及多轮续接要求；具体模型能力与价格需在部署时核实。

2026-11-08 另以 DashScope OpenAI 兼容地址和 `qwen3.8-max` 尝试反馈样本的真实规划。固定容器 Worker 和 500 美分目标已创建，但请求在 120 秒客户端期限内没有返回，SQLite 只保留 32 美分 `uncertain` charge（`httpStatus=0`、`transport_error`、空 usage/response ID），没有方案、任务、源码、制品或独立质量记录。试用凭据已删除；该次失败不能判断模型名或供应商根因，也不构成 P2/P3 证据。下一次接入须使用轮换凭据，先完成有界的供应商/模型可用性核对，再决定是否重试同一反馈范围。

完整 P3 还需要原生端与真机、合法签名、正式账户、渠道实际审核/上架、运行验收及企业治理验证。本手册不将这些标记为已完成。
