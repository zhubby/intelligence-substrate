# 源码范围拒绝后的纠正

代码 Agent 提交的完整快照包含越界改动时，控制面先拒绝采用。若响应明确证明尚未创建候选，Agent 可以在原任务内撤销意外改动、保留允许的工作并重新提交。该流程沿用已批准的需求、方案、源码基线、范围、租约及累计预算。

## 可继续的拒绝

只有完整快照接口在第一事务的真实 Git 范围检查失败，且尚未创建提交、prepared 操作、change 或候选引用时，返回：

```json
{
  "error": {
    "code": "source_write_scope_rejected",
    "message": "源码变更超出已批准的 writePaths 范围……"
  }
}
```

HTTP 状态为 409。消息保留范围和路径提示，供 Agent 定位需要撤销的修改。失败请求不占用成功幂等结果，因此同一有效执行可以提交新的准确快照。

普通 `conflict`、403、请求取消、传输或响应解码失败均不提供这种保证。旧文本提交、prepared 候选的第二事务及人工恢复也不返回该纠正标记。它们继续执行原核对流程；不能据“没有收到成功”推断“没有候选”。对结果不明的提交，Worker 只按既有策略最多三次重放同一快照字节，不带入新修改。

## 恢复绑定基线

Agent 使用一个精确文件路径撤销修改：

```json
{"action": "restore_base", "path": "frontend/ui.txt"}
```

- 仅适用于 `code` 工作项。来源只能是领取时 `sourceBinding` 的准确仓库和提交，不能传入 `commit`、`repositoryId`、`content` 或其他字段。
- 原文件存在时恢复其原始字节及执行权限，包括二进制和被删除的文件。即使同名分支后来推进，也仍读取原绑定提交。
- 原文件不存在时，只删除该路径上的一个普通文件；不存在时按无改动处理。
- 拒绝目录、符号链接、路径穿越、Git 元数据和非规范路径。不会递归清理目录。大小写别名不能被误当成基线文件不存在。
- 使用临时普通文件替换原文件，避免通过现有硬链接改写外部目标。新缓存放在控制器私有目录，不进入工作区或源码快照。
- 集成任务仍以绑定的基础提交为准；恢复冲突路径后重新登记准确决定。原父输入和最终全部路径仍经过范围检查。

恢复不会授予新的修改范围，也不扩大文件读取权限。它是精确撤销工具；进程、网络和宿主隔离仍由执行后端负责。

## 同一任务继续

1. `finish` 收到专用拒绝后，将拒绝作为观察交给模型；不会将任务记为成功。
2. Agent 恢复意外改动，运行必要检查，再次 `finish`。每次提交生成独立私有快照，仍通过完整 Git 门禁。
3. `restore_base` 按普通工具保存意图、确认观察及准确文件检查点。工具结果不明时仍需人工核对，不能直接重放。
4. 明确拒绝后可以保存纠正进度、发送澄清并显式等待。换节点恢复继续使用原源码、范围和累计额度。
5. `finish` 本身仍不是普通持久工具步骤。被拒绝的完成尝试消耗现有最多 24 步额度，不重置模型费用或活动时间。耗尽后阻塞，未纠正源码不能进入构建。

Worker 保留“曾经提交”的历史。仅明确未采用的范围拒绝允许后续检查点；未知提交结果继续停止核对。受控停止时不会偷偷再提交，失败源码可保存为私有 `local_only/incomplete`，不能作为成功源码或质量证据。

需要扩大范围时，由负责人审查新方案并批准；不能以恢复工具、旧候选或换节点追认新的权限。成功提交之后，代码评审、独立质量验证和正式发布审批仍分别执行。

## 验证与接续

定向回归覆盖专用拒绝、普通分支冲突、prepared 故障、原版本恢复、二进制/执行位/删除、链接/目录/大小写边界、等待换节点及 24 步阻塞。固定模型动作另经真实认证 HTTP、Git 和 Worker 保存，由 Python/SQLite/Git/tar 独立读回实际结果。两条正向流程产生的文本包和本地独立 QA 只验证协议，不能代表业务应用或真实模型开发能力。
