# 完整应用 HTTPS 预览验证

主线程沿用已批准平台规划，复用 028/029 的入口、专用包、真实 Worker 和独立节点。本项为部署验证补充，不改变产品设计或质量规则。

1. 保存源码、输出、Git 索引、原 18080 服务、Docker 和 AVD 基线。
2. 为真实应用验证器增加可选的受限 HTTPS 入口配置；默认 HTTP 验证继续可用。TLS 模式使用 Secure 会话和非开发模式预览入口；Worker 仍经私有 loopback HTTP 与控制面通信，此边界明确记录。
3. 新增可重复的本地编排脚本：私有 CA / 叶证书、准确 SPKI、Chrome 局部 DNS 映射、实际 Caddy 模板、两应用真实构建。不得改系统信任、全局忽略 TLS、修改原服务或调用付费模型。
4. 实测桌面/移动业务、准确包/提交响应、私有文件拒绝、host-only 会话及预览无凭据；模拟真实控制面离线，经 HTTPS 返回失败，重启后原数据/链接保留；停止后所有入口失效，清理专属执行资源。
5. 验证只有预览资源时 `measurements.record` 拒绝，测量、质量和发布数据均不被伪造；保持独立运行证据规则。
6. 运行脚本语法、编译和必要真实浏览器验证。仅当运行时产品源码发生变化或出现新问题时扩大回归；先前通过的全量检查不机械重复。
7. 主线程复查；输出中文报告、操作手册、脱敏证据、源码包及四张截图，独立读回与原环境保全。只关闭 030，完整多端正式交付/P3 继续开放。

成功仅证明当前本机拓扑下完整应用 HTTPS 开发预览，不证明公网/企业网络、公开 CA、macOS/iOS/Windows 原生运行、真机、签名、商店或正式交付。
