# 源码提交拒绝后的受控纠正

> 顺序在主线程实施；用户规则禁止子Agent。沿用已批准的完整产品规划，不暂存、提交或推送平台仓库。

**目标：**普通代码Agent收到明确的、尚未创建候选的范围拒绝后，能在原任务/租约/范围/累计预算内恢复意外改动并再次提交。未知结果、分支冲突和权限失败继续停止核对，不视为可纠正拒绝。

**当前证据：**055已强制实际Git范围；但agent.go的finish遇commitSource错误直接结束，source.go固定snapshot.tar的O_EXCL及commitTried也阻止同一执行再次提交或保存进度。工具无.git元数据，直接write又禁止修改保护路径，因此还需要只能恢复原始版本的精确工具。

## 设计

- 只在CommitSnapshot第一事务的真实范围检查失败、尚未创建commit/prepared/change/ref时返回409错误码source_write_scope_rejected。旧文本入口与prepared第二事务不授予此标记，普通409/403/传输失败不自动继续。
- Agent将该明确拒绝作为观察反馈，继续原有最多24步/累计模型预算。重新提交重新生成完整不可变快照，失败幂等结果不消费成功键；不复用未知请求的不同字节。
- 新restore_base工具只接收path，在code工作项内从控制面读取领取时绑定base，恢复准确字节/执行权限或原本不存在时删除一个普通文件。不能选择commit/repository/任意content，不递归删除目录、不跟随链接。它是撤销修改，不授予新的修改范围。
- 固定基线缓存位于controller-owned私有目录；集成同样使用绑定base，冲突路径恢复后重新登记准确决定。restore_base进入现有持久工具进度，恢复后继续原绑定和额度。
- commitTried保留提交历史以阻止停止保存时自动再提交；只有明确未采用的拒绝设置commitRejected，允许保存后续检查点。重新提交清除该明确状态，未知结果继续停止核对。代码结果继续经过055真实Git门禁与独立质量流程。
