# 真实模型研发闭环实施计划

> 按已批准产品计划继续顺序实施；不启用子 Agent，不提交或推送，保留现有 18080 服务和 87 份输出。

**目标：** 用真实提供方完成需求规划、受控代码生成、源码固定、制品构建及独立业务测试，记录真实模型用量和局限。

**方案：** 沿用现有受治理的 Chat Completions 接口，凭据仅由控制面读取。目录查询确认现有 AUTH_TOKEN 与 kimi-k2.7-code 可用；另一 API key 的 401 不再代表所有访问路径。已通过一次完整 JSON 生成探针。官方 CLI 没有单次输出 token 上限，本轮不接入；不新增暂时不需要的 Responses 适配。

**实现与验收：**

- [x] 先写并执行失败测试：非有限价格、非整数输出限制、截断/拒绝/无有效内容、未知用量不能放行；费用保留上界并记录提供方身份。
- [x] 在现有网关落实严格边界，并将规划上下文补为当前项目的版本化知识、仓库及已注册节点；不传凭据或其他项目内容。
- [x] 在无外网、只读根目录、无平台凭据的容器 Worker 中，让真实模型生成客户反馈和服务预约 Web/API 应用。使用固定 Node/Python 工具镜像与无第三方依赖的应用，不改变既有 Flutter 参考项目。
- [x] 由模型生成方案，经本地验收负责人明确检查批准后执行；独立 API 和真实浏览器已验收最终准确制品。预约经过人工重新规划、模型修复 UI；反馈经过人工固定命令修复一个状态路径表达式。两者均保留原阻塞缺陷，不声称完全自主修复成功。
- [x] 完成相应回归、主线程复查、现场保留和新命名交付导出。区分真实模型/真实容器/真实浏览器与真机、签名、渠道、企业生产验收，整体 P3 保持未完成。

验收使用合成业务数据和本地负责人身份，不构成企业真实批准。提供方价格页面使用人民币，平台验收暂采用显式保守美元费率，保留 token 用量与来源，不将估算费用称为账单金额。等待或失败不得制造成功证据。


追加验证与实施：已先复现再修正网络期间需求版本变更导致旧方案绑定新基线、Agent 丢失提供方续接字段、固定 4096 输出预算无法配置及旧方案任务进入当前模型上下文。新增有限默认输出预算与数据库持久调用间隔；排队重查策略/基线并在取消时不预留费用。真实 429/500 和已计量截断均保留记录，未伪造退款。

真实验收在原目标与预算内顺序进行。反馈原任务达到重试上限后由本地验收负责人批准后端→界面→构建的新方案，旧任务、执行和费用仍保留。最终两个业务均有真实源码/构建、同制品的独立 API 与浏览器证据及 awaiting_approval 候选，但未批准、部署或发布；P3 保持未完成。


推理适配：根据官方 kimi-k2.6 文档增加管理员受限 `thinking.type` / `reasoning_effort` 选项，拒绝未知字段或覆盖预算/模型/消息。较早思考模型在 4096 输出上限截断，另一次请求在 120 秒超时；后续简单业务验收采用提供方支持的 disabled 设置及 4096 输出预算。模型曾输出空 sourceFrom 被严格拒绝，后经版本化知识反馈重新规划；曾在开发自测中循环并触发工作项预算门槛，新方案把运行测试留给独立 QA，不增加总预算。

最终质量处理：预约 UI 的时段 ID 与凭据输入错误由真实浏览器识别；自动修复预算停止及输出截断后，人工批准模型 UI 修复/构建替代方案。反馈有效 POST 因绝对状态路径断开连接，模型替代修复也在提交前达到预算门槛；没有持久候选可恢复。随后人工批准平台固定命令，仅替换路径表达式，页面字节不变，接管阶段无模型调用。原 QA 没有改动，原失败报告与 blocked 缺陷保留。预约估价累计 345/500 美分，反馈 430/500 美分，uncertain 上界均未清零。
