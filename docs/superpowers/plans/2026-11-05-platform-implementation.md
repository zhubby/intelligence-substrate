# Intelligence Substrate Implementation Plan

> For agentic workers: execute sequentially using superpowers:executing-plans. The repository's user instructions prohibit subagent dispatch.

**Goal:** Build an executable enterprise delivery control plane and integrated workbench, with enforced governance and truthful external integration boundaries.

**Architecture:** A modular Go API owns durable business state and transactional audit/outbox records. React consumes the same versioned API. Git, workers, model access, AX and release channels sit behind explicit interfaces.

**Tech Stack:** Go 1.27.1+ (AX v0.3.1 schema dependency), database/sql with SQLite and PostgreSQL, React/TypeScript/Vite, native Git, container deployment.

**Spec:** ../specs/2026-11-05-intelligence-substrate-design.md

## Global constraints

- Human approval for requirements, significant plans and production release.
- No fabricated native-build, device, model, cluster or store success.
- Project-scoped identity; independent quality; immutable artifact and approval bindings.
- No plaintext integration credentials in stored task payloads.
- Tests exercise permission boundaries, invalidation, failure, concurrency and recovery.

## Implementation rulings

- Use a feature branch in the empty repository; no worktree can be based on its unborn HEAD.
- Keep execution in the main thread, following the user's AGENTS instructions.
- Native Git is the repository engine; platform policy wraps its transport and review operations.
- SQLite provides a zero-service local environment; PostgreSQL is the deployment database. Both use transactional mutations.
- Native and store execution require trusted workers/connectors; unconfigured integrations remain blocked.
