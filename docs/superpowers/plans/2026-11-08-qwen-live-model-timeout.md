# DashScope 真实模型接入超时后的受控接续计划

> 顺序在主线程实施；保留 `work/live-qwen38-feedback/` 原始失败状态，不自动重试、不提交、不推送，不操作商店、生产、签名、真机或 Apple 许可。

## 目标

在已轮换凭据和供应商可用性得到独立核对后，重新验证同一受控反馈 Web/API 样本的需求规划、容器开发、制品和独立质量链路。一次供应商响应前超时不能被改写为成功，也不能用新预算覆盖原始不确定费用。

## 当前事实

- `qwen3.8-max` 规划请求运行 120 秒后 `httpStatus=0`、`outcome=transport_error`，没有 response ID、provider model 或 usage。
- 独立 SQLite 只产生一笔 32 美分 `uncertain` charge；没有方案、任务、源码、制品、QA、候选或发布。
- 运行使用固定 digest 容器、`allowNative=false`、4096 输出上限和 500 美分总预算。
- 测试用私有凭据文件已删除，凭据正文未写入源码、文档或导出物。

## 接续步骤

1. 负责人提供已轮换的凭据文件路径；控制面只读取权限为 0600 的普通文件，不在命令行或日志中传递密钥正文。
2. 先执行不生成模型内容的供应商连通性和模型可用性核对，确认兼容端点、确切模型名、账号权限和超时边界；核对失败时保留失败证据，不启动完整验收。
3. 在同一应用范围内重新生成待审方案，沿用固定容器镜像、预算、源码范围和独立 QA；不并行启动 booking 样本。
4. 独立读取 `result.json`、SQLite charge/audit、Git 引用和制品字节，确认真实模型、真实容器和独立质量各自的状态；完整产品 P2/P3 仍按产品验收表判定。
5. 测试结束立即删除临时凭据文件，并在结果中保留 provider response、usage、费用状态和任何人工介入边界。

## 验收标准

- [ ] 轮换凭据可用，权限和来源经过独立核对。
- [ ] 供应商健康/模型核对在有界时间内完成，未泄露凭据且不把健康响应当成模型业务成功。
- [ ] 真实模型规划和受控开发有完整 response/usage，预算按实际 token 结算；异常用量仍保留 `uncertain`。
- [ ] 独立容器构建、独立业务 QA 和浏览器门禁分别有准确绑定证据。
- [ ] 任何超时、截断、拒绝或外部结果不明都停止后续动作并保留原状态。
