> **For agentic workers:** Use superpowers:executing-plans sequentially in the main thread. User instructions prohibit subagents and Git staging/commits/push in this platform checkout.

**Goal:** 以同一个反馈应用和五端需求为基线，让真实本地模型在预先分解的蓝图配方内形成方案并修改共享 Flutter/Go 源码，再由平台执行准确源码构建与独立业务验证，保留未通过端的实际缺口。这项试验不单独证明模型能自主拆解任意企业需求。

**Architecture:** 复用现有 Chat Completions、方案生成、受保护 Worker、Git 快照及自动质量调度。独立 Ollama 仅监听 127.0.0.1:18384，权重与临时数据置于本轮私有 work 目录，禁用 cloud；默认 11434 服务不改变。开发命令使用已有 digest 固定、无网络的容器；可信 macOS 节点使用已安装 Flutter/Go/Android 工具执行固定构建，外置质量脚本不向模型开放修改权限。

**Tech Stack:** Go 1.27.1、现有 Python/Node/Playwright、固定 Flutter 3.47.9、Ollama 0.40.13、qwen2.5-coder:7b。

**Spec:** [已批准平台产品规格](../specs/2026-11-05-intelligence-substrate-design.md)；[产品验收接续](../../product-acceptance.md)。

## 已取得的现场证据

2026-11-07：原蓝图的同一 `9612c66d00caceab7ea52bcb4c608287586cf845` 提交共 143 份文件，实际 Worker 完成 Web 与 Android debug 构建。两条外置质量流程分别先通过三项原业务检查，再因省略 priority 未持久化 normal 而实际失败；保留 failed 执行、blocked 缺陷、准确报告与截图，尚无模型调用、通过证据或发布候选。独立 Python 从原 SQLite 备份、Git 和报告/制品字节核对了同一提交与全部 143 份源码。190 项 Python 回归通过，零跳过；已查看实际 Chrome/Android 失败现场截图。

原始 red 验证器字节已私有归档。随后将新增 Web 优先级场景中的手机初始可见记录改为桌面刚提交的最新记录：新增多条记录后，原最老记录可能在 ListView 屏幕外；关闭优先级参数时原断言保持。这不改变已触发的默认优先级失败点，最终绿验收仍须使用当前脚本实际运行全部业务场景。

模型推理前进一步固定契约边界：显式空字符串、错误大小写、前后空格和未知优先级均必须 422 且不写入，只有省略字段采用 normal。Web 桌面/390px 与 Android 均实际中断提交连接，再恢复后直接重试，核对用户输入和 urgent 选择保留；成功后下一条恢复 normal。最终质量必须包含这些场景，不能将原 red 的三项通过扩称为已验证了尚未到达的场景。受影响 Python 输入变化后另存并执行回归，保留先前 190 项原记录。
