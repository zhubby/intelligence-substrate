# 中断源码的人工核对与接管

本增量落实原产品规划的故障恢复、人工接管、来源追溯与权限约束。沿用已批准的交付控制面，不创建新工作流引擎，不修改生产发布权限。代码继续保留在当前未提交的功能分支；按用户约束在主线程顺序实现。

## 问题与取舍

快照已经持久化候选及生产者后，Git 更新与 SQL 确认之间可能中断；也可能 SQL 已确认，但 Worker 尚未报告完成就失去租约。原租约内的精确重放不能解决这两类跨租约中断。自动重跑会遇到固定目标分支已变化，甚至制造重复工作。

采用负责人显式核对原候选的方式。相比重新授权旧租约，这能保留旧身份失效事实；相比强制覆盖目标分支，这能保护已发生的后续变更。首次实现不自动重执行命令、不提交新代码、不创建测试证据。

## 契约

- `GET /api/v1/source-operations/{id}` 返回有权限项目内的操作、候选、当前目标分支、可采用/停止采用状态及阻塞原因；不得返回租约令牌。MCP 提供同等只读检查能力。
- `sources.reconcile` 参数严格为 `id,key,commit,observedHead,decision,reason`。decision 为 `confirm` 或 `abandon`，commit 与 observedHead 使用完整 SHA（不存在分支时 observedHead 为空）。每次决定绑定操作、操作者、观察到的分支及原因。
- 仅项目 owner 或站点管理员的人类可以决定。Agent、普通开发者、跨项目身份均不能决定。幂等重放需要相同主体、key 和完整请求；同一操作最多一个决定。
- 确认只接受 prepared/committed 原操作、控制面保留的精确候选，以及目标分支已包含候选的事实；需要当前需求、批准方案、原始 task/run 和源码绑定一致。不得确认活跃租约或已有其他成功/活跃执行的工作项。停用节点的原产出可以由负责人核对，节点身份不会被恢复。
- 停止采用保留候选引用、原作者和审计，不移动任何 Git 分支；允许关闭旧需求或旧方案的候选，但不复活已取消/过期工作项。需要继续开发时使用仍然有效的原任务重试或新批准方案，目标分支检查继续生效。
- 决定及 op/change/run/task 状态在一个 SQL 事务中提交。失败后不留下半个决定；重放不重复成功记录或覆盖后来推进的分支。所有受控 Git 写入口与此核对共用现有 Store 事务锁。

## 可信来源与生命周期

确认保留原 change.authorId、run.workerId 和原源码操作；使用单独 `source_recovery` 对象记录人工决定。原 run 状态为 `recovered`，task 为 `succeeded`；run 不伪造退出码、租约或 Worker 完成摘要。原日志保留在原执行，已有结果及状态附在决定中。后续源码选择同时支持可信 succeeded 和 recovered 来源，但 recovered 必须核验决定、原操作、源码绑定与原作者。原 Worker 不可再心跳、提交或完成此 run。

快照 prepared/committed 但 Worker 未正常完成时，失败/过期后的工作项进入“源码待核对”，保留固定输入且不消耗新尝试；通用重试不能绕过。源码确认只放行后续构建，质量策略、评审独立性与发布门槛保持现有校验。集成恢复沿用原 integrationId、冲突决定摘要与所有批准父输入。

## 工作台

在现有执行记录内展示待核对候选和“核对源码”入口，避免新增仪表盘。弹窗加载实时状态，展示完整候选与分支 SHA、原作者、运行状态、阻塞原因、下载原候选链接及历史决定。具备权限时填写原因后选择采用或停止采用；提交失败保留输入并允许刷新观察。桌面和手机均验证键盘打开、Escape 焦点恢复与无横向溢出。

## 验收

真实 Git/SQLite 故障注入覆盖 Git 后 SQL 前中断、已确认但未完成、过期/失败/停用节点、当前与其他活跃租约、分支后续推进/无关移动/删除、候选引用变化、旧方案/需求、集成父历史与决定、幂等/并发/事务回滚。真实 PostgreSQL 双客户端检验唯一决定和备份恢复。HTTP/MCP 验证鉴权与令牌隔离。浏览器验证负责人闭环、无权身份、刷新和错误状态。完整 Go race、前端构建及现有浏览器套件回归。

本增量不证明真实模型、AX、宿主机沙箱、原生应用/真机、签名、正式渠道或完整企业运维验收。
