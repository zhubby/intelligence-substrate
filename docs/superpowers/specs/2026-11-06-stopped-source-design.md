# 代码 Agent 中断源码保存

## 背景与原产品要求

原产品规划要求 Agent/节点中断后可恢复，工程师可随时接管，任何实现仍需独立质量与人工发布批准。真实反馈应用的模型在 write/run 后遭遇工作项预算门槛，未执行 finish，临时目录被移除；已有 source_recovery 只能核对已经保存的候选，不能恢复这些文件。本增量补齐这个已测得的源码丢失路径，整体多端交付目标保持不变。

## 行为

- 执行普通或集成 code 工作项前记录准确输入源码摘要，遵循现有完整源码选择规则。
- Agent 非正常返回且源码实际改变时，将准确源码 tar 和无凭据来源元数据写入可信 Worker 状态目录的私有 stopped-source 子目录。写入成功和同步失败分别报告；不宣称未落地文件可恢复。
- 输入未变时不创建无意义候选。只读分析任务不保存代码候选。源码路径、模式、删除、忽略规则及 64 MiB/20,000 条目上限沿用现有协议。
- 原上下文仍有效且尚未尝试最终源码提交时，按原 run、租约、任务输入、目标分支和快照幂等键尝试登记中断候选。接口或绑定拒绝不能绕过，已发起的最终提交不另造第二次操作。
- 成功登记后原执行仍保留非零退出、原错误与日志，任务进入已有“源码待核对”，Agent 不能自行采用。负责人可通过已有 source-operations / sources.reconcile 核对候选；采用后保留原生产者，并继续实际构建、独立验证和发布批准。
- 网络、租约、基线或集成冲突阻止远程登记时，本地私有快照继续保留，附准确摘要和同步错误。此副本没有自动导入/跨节点恢复授权；管理员需人工核对后按原规则另行处理。

## 边界

本增量保存受控返回时已经生成的源码；不是模型会话或工具步骤检查点，不承诺 kill -9、宿主失联、硬盘丢失或未结束命令的恢复。中断前的工具不会自动重放，不清零预算/不确定费用、不增加重试次数、不补造 finish 或测试结果。对端是否接受不明时沿用原 prepared/committed 源码核对协议。

本地快照不包含平台令牌、租约、模型对话、reasoning_content、数据库或质量制品。源码本身仍可能包含企业敏感资料，保存在可信 Worker 私有目录，不公开分发、不自动删除或上传到第三方。

## 验收

1. 真实认证 HTTP/Worker/Git 路径：一次源码生成后由真实预算检查阻止下一模型请求，源码候选与私有 tar 准确保留，执行没有成功或产生质量证据。
2. 原节点无权采用；独立人类负责人采用后，后续构建使用准确候选，原独立 QA 实际执行，CI 证据不绕过浏览器发布门槛。
3. 无修改、非 code、失效基线/租约、上传失败、危险路径/链接/超限，以及最终提交已开始的情形没有伪造成功或重复操作。
4. 私有源码包含工具生成字节、删除与模式变化，凭据和元数据不混入源码；状态目录重开后文件仍能核对。
5. 现有源码接管、集成、修复/重建/独立复测、PostgreSQL 并发与备份保持通过。原 18080 服务和 97 份输出保留，不提交推送。
