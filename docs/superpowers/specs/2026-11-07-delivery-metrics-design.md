# 交付效能观测设计

本模块执行已批准产品规划中的效能测量要求。当前授权覆盖常规实现和验证；不新增模型付费、渠道提交或生产发布。属于现有控制面的独立观测模块。

## 方案与范围

选择「平台观测 + 明确的人工作证记录」。仅从任务、测试数量推算业务指标会混淆技术验证与业务验收；完全手填指标又缺少版本与产物约束。增加受控事实记录，再提供只读统计。沿用通用资源存储、事务鉴权、审计与幂等机制，不增加分析数据库、后台数据仓库或新的发布门槛。

### 人工记录

`measurements.record` 支持四种类型。人类项目 owner/product/quality 可登记；人工投入只代表登记人本人。Agent/Worker 不得登记或作废这些事实，即使其持有相同项目角色。

- `preview`：明确确认某个可运行制品，引用同目标、需求版本的独立通过证据；排除 CI、纯原型和发布证明。保留准确制品、提交、报告摘要和实际验证环境。首次确认的服务端记录时间减对应 requirement.CreatedAt，表示平台首次确认预览的耗时。
- `business_acceptance`：引用同目标、需求版本的候选版本与实际报告，显式记录 passed/failed。记录时间由平台生成；按该时间和稳定 ID 排序判断首次结果，后续通过不会抹掉首次失败。这是人的业务判断，不改变独立质量门槛、审批、发布或目标状态。
- `human_effort`：登记本人已结束的投入区间，区间在当前需求版本创建之后，每条不超过 24 小时；跨目标也不能重复计算同一人的重叠时间。累计单位为人秒，不是交付日历时长；未登记投入仍未知。
- `production_defect`：引用确已发布的版本和报告，使用项目内唯一来源标识登记一项缺陷。技术测试失败、运行告警不自动作为上线业务缺陷。

所有记录要求来源标识、依据说明、幂等键。预览、业务验收和投入绑定当前需求版本；晚到上线缺陷归于其所引用候选的原需求版本，使用准确的原版本报告。预览、业务验收、上线缺陷需可读取且摘要正确的实际报告；版本和制品绑定由服务端派生。幂等重试返回同一记录；同来源不能跨目标或登记人重复计数。`measurements.void` 保留原始内容、作废人、时间和原因；重新登记链接被替代记录。已作废原请求的重放不能复活记录。需求变更保留历史事实，当前版本统计隔离旧数据。作废后统计重新计算并明确这是已登记的有效记录口径，不宣称穷尽业务历史。

### 渠道观测

新建候选时为每个目标写入初始 ready 状态与平台观测时间；所有 setTarget 状态转换追加不可由用户提供的历史。不变的外部查询不重置开始时间。processing、awaiting_review、awaiting_release 的区间单独累计；并行渠道为「渠道秒」，不是端到端等待时间。旧候选从首次新增观测开始计时，缺失的此前区间明确显示不完整；不得根据 updatedAt 倒推。需求变更截止旧版本的等待观测。

## 只读报告

`GET /api/v1/projects/{id}/delivery-metrics` 与 MCP `delivery_metrics` 返回相同、无密钥的结构化报告。默认选择项目各目标的当前需求版本；可用 goalId 筛选，指定 revision 时必须同时指定 goalId。使用事务内当前身份与项目权限，不信任缓存角色。报告列出各需求版本的来源 ID、统计样本与未覆盖数：

- 需求到首次确认预览：仅已记录样本的均值及样本数，无样本为 null。
- 首次业务验收通过率：首次结果为 passed 的需求版本数 / 有业务验收记录的需求版本数；未观察版本单独显示，不计为失败。
- 人工投入：已登记有效区间的人秒；无区间为 null。
- 上线缺陷：已登记数量及关联版本，零条仅表示没有登记，不能证明无缺陷或完整观察窗口。
- 发布执行失败率：publish/publish_continue 的 succeeded/failed 执行记录中 failed 的占比。排除状态轮询、未完成、失效租约和取消；这是操作执行口径，不等同版本最终发布失败率。分母为零时为 null。
- 渠道等待：平台实际观测到的渠道秒，明确完整性和持续等待；不计入 Agent 活跃执行时长。
- 成功交付完整成本保持 null，现有账本只有已登记费用，不能升级为完整真实成本；提供现有成本入口。
- 人工研发对照基线和可比提升幅度尚未采集，明确标记缺口，不预置收益百分比。

统计为观测事实，不是交付验收判定。历史成功不赋予当前版本发布权；历史预览、业务验收不补当前需求版本的缺口。若依赖报告或制品字节丢失/损坏，保留原记录并将其排除统计、列出核对原因。

## 体验与验证

在企业治理现有页面增加「交付效能」视图，支持项目/目标选择、需求历史、清晰样本口径、记录/作废及来源查看。使用现有弹窗与表单，显示加载、错误和重试状态；切换范围后不显示前一范围结果。桌面与移动端验证键盘、Escape、焦点恢复与横向溢出。

测试先行：真实 SQLite/文件字节/HTTP/MCP、事务回滚、当前权限、幂等与并发、版本隔离、首次失败后通过、缺失与明确零值、渠道等待与旧数据覆盖、发布执行分母、恶意跨目标/版本绑定、损坏附件。使用隔离 PostgreSQL 全量 race 回归，独立 SQL/备份读回验证事实持久化。既有预览、索引、输出、Docker 及 AVD 保持原状。

## 自审

指标分母、单位、时间来源、缺失值、人工与平台观测边界均已定义。真实业务试点、完整成本、人工对照基线和 P3 正式多端交付仍需后续工作；绿色自动化不等于这些完成。
