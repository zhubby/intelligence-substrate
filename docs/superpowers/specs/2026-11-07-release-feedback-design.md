# 已发布版本的晚到问题报告

本增量落实已批准产品规划中的运行反馈、后续迭代和准确版本追溯。现有上传把报告绑定当前需求版本；旧版本继续服务时，无法保存新发现的问题依据，历史效能页也禁止登记。

## 行为与权威边界

- 新增 `POST /api/v1/releases/{id}/reports?artifactId=...&name=...&key=...`，请求体是 1 B–16 MiB 的普通报告文件。只接受唯一、完整的三个参数。报告始终下载为附件，不渲染上传内容。
- 仅当前有 owner/product/quality 权限的人类可上传；发布单角色、开发者、只读成员、Agent 和 Worker 不可上传。读取与下载沿用项目权限。上传前与提交事务内都重新验证当前身份、成员资格及来源。
- 来源必须为准确候选清单内的 package，核对项目、目标、需求版本、仓库、提交、摘要及实际字节，且该准确目标已有 published/verified 观测。旧 `delivered` 状态按原全端交付语义兼容。需求改版、删去客户端、候选成为 stale 或发布后暂停不抹掉已观测的发布历史。
- 平台派生报告的需求版本、仓库、提交和目标，保存 releaseId/releaseBinding/releaseArtifactId/releaseArtifactDigest，标记 purpose=release-feedback。不修改原候选、制品、需求、批准或渠道。
- key 按项目与登记人去重，准确输入含报告摘要/大小/名称和候选绑定；成功重试返回同一报告，改变字节或来源复用 key 返回409。幂等、报告资源及审计同一事务。失败上传清理临时文件，已写入的内容寻址字节可能保留但不成为有效业务资源。
- 此报告只作为线上问题的人工依据，不能用作需求业务验收、独立质量/环境/发布证据、商店资料或运行恢复证明。

## 晚到缺陷与界面

- `measurements.record` 的 production_defect 可以显式声明所引用候选的需求版本。平台仍派生最终版本，并核对报告所属准确候选、制品、发布目标和字节。其他观测继续要求当前需求版本。
- 当前与历史效能页均可由授权人上传问题报告、登记上线缺陷，历史页的预览、业务验收和本人投入保持只读。缺陷归旧版本，当前版本不增加计数；作废、更正和来源去重沿用原机制。
- 工作台冻结弹窗的目标/需求/候选选项与重试 key，显示版本及目标，使用原生文件选择、点击、键盘/Escape/焦点恢复及错误重试。上传成功不自动声明有缺陷或已修复。
