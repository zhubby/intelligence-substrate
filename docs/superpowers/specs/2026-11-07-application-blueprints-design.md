# 平台内应用蓝图

本增量将已批准产品规划中的标准多端蓝图接入既有交付控制面，不改变需求、方案、独立质量及正式发布审批。

## 对象与权威

管理员配置本机发行资产目录。控制面只加载内置 `flutter-go-v1` 的明确资产集，拒绝链接与特殊文件，加载后保留不可变内存快照。目录摘要包含模板、生成规则版本及辅助脚本的字节和执行位；不接受请求中的文件系统路径、URL 或自定义生成命令。

`blueprints.propose` 为当前已批准需求保存不可变提案：应用名、反向域名、feedback/booking 模式、可选空仓库、来源目录摘要、生成归档摘要、大小、文件数和绑定摘要。源码生成不执行模板或 Flutter。归档进入现有内容寻址制品存储；提案本身不属于可发布应用制品。

方案通过提案 ID 和预期绑定摘要选择蓝图。省略选择时可以沿用当前批准方案的蓝图，同一需求新方案默认不重新初始化。新需求版本不自动继承旧蓝图。`initializeBlueprint=true` 必须有选定蓝图；控制面派生一个初始化工作项并把源码任务依赖接到它，模型不能自己注入初始化字段。

人工方案批准保存完整蓝图快照、快照摘要和原方案绑定。方案、提案、初始化任务、执行记录、源码归档及提交形成可追溯链。

## 执行与失败边界

初始化是现有开发工作项中的固定控制器动作，不调用模型。领取时固定空 Git 提交和功能分支的预期状态；不向主分支写入。Worker 以有效租约读取冻结归档，验证摘要后提交现有源码快照 API。控制面重新验证归档必须与已批准蓝图完全一致，并沿用持久提交意图、Git CAS、幂等重放和人工恢复。已有源码或分支偏移进入明确阻塞状态。

初始化不能拆分；依赖重排不能移除源码任务对它的依赖。后续工作使用现有源码生产者链。初始化不形成测试、安装、签名、审核或发布成功证据。

归档自带原生工程准备辅助脚本。Flutter SDK 准备仍是另一个明确批准的开发命令，真实平台构建、目标系统验证、合法签名与渠道发布分别验收。参考后端仍为单实例 JSON 状态示例，选用蓝图不表示满足生产容量或业务安全要求。

## 用户流程

在目标的交付方案页查看可用蓝图、创建提案并选择具体版本；人工编制及模型生成共享选择。审阅和批准页显示业务模式、应用标识、版本及初始化选择。沿用现有表单、错误和加载状态，以及桌面与移动布局。

## 验证

先验证缺失行为的真实失败，再验证提案幂等与隔离、冻结输入、方案/模型输入绑定、未批准与旧基线拒绝、非空仓库与摘要篡改拒绝、动态依赖约束、并发与备份恢复。使用真实 HTTP、Worker、Git 为两个业务生成源码并运行后端检查；本机浏览器检查桌面和移动流程及截图。完整回归不使用付费模型、不操作原预览或真实商店。
