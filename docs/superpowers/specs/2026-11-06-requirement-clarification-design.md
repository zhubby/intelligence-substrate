# 需求澄清与基线决策

本增量落实已批准规划的“业务目标 → 需求澄清与验收基线”，在现有目标/需求/计划链上增加可追溯问答。授权来自用户的完整实施计划和持续“继续”；主线程执行，不重复请求设计许可，不创建子Agent或Git提交。

## 问题与取舍

现在用户必须直接填写验收标准，业务问答没有结构化状态，批准也不会检查未决问题。采用同数据库的版本化澄清记录，复用权限、幂等、审计与备份；自由文本聊天缺少明确待决状态，独立需求系统则使现有批准和模型上下文分离。

## 业务契约

- `clarifications.propose {goalId,expectedRequirementRevision,key,questions:[{question,context}]}`：同项目product/architect/developer/analysis/design或owner可提问；Worker不通过此入口工作。仅当前未批准的需求版本可新增。每批1–10问、当前版本最多100问；question最多2000字节，context可空且最多2000字节；拒绝混合类型、额外字段、重复的规范化问题。服务端分配问题ID，客户端不能指定答案、确认人或生成来源。
- 每批保存为`clarification`资源，固定需求版本、提问人和来源。每问初始open，整批在全部回答后变为answered。
- `clarifications.answer {id,questionId,expectedRequirementRevision,key,answer}`：只允许当前有product/owner权限的人类，答案1–12000字节；保留确认人、姓名和时间。首次回答后不可覆盖，同请求回放、换内容冲突。需更正时创建新需求版本，历史保留。
- 提问与回答不会修改业务结果、验收标准、必选端、预算，也不会自行批准基线。未决问题阻止当前基线批准；审批事务绑定当前版本全部问答的准确快照和摘要，并仍记录原验收绑定。批准后问答冻结；有新问题先走需求变更。
- 需求变更后旧问答只读保留，不自动成为新版本答案；可在新版本按实际需要重新提问。历史答案不自动修改验收条款；人必须在批准前核对业务结果、验收标准与问答一致。
- 有权限的现有目标仍可采用人工已完善需求直接批准，没有问题记录不声称已经过智能澄清。

## 模型辅助与受控执行

`POST /api/v1/clarifications/generate {goalId,expectedRequirementRevision,key}`只向人类product/owner开放。使用当前目标和本项目当前知识/问答生成一批澄清问题，不能生成答案、扩大范围或批准需求。

需求尚未批准时允许此专用、只读推理步骤；通用`/model/chat`、方案和开发仍要求基线批准。草稿授权由服务端私有调用参数和持久生成请求共同决定，不能由HTTP字段绕过。沿用外部模型策略、输出/上下文/次数/预算、持久调用间隔、费用预留和不确定费用规则；预留事务重新验证当前身份与项目权限。

生成前持久保存`clarification_generation`请求及幂等内容。一个key只启动一次提供方调用；已完成回放原问答，进行中/失败回放明确状态，不自动重发。模型失败、非法结构、基线变更、批准或权限撤销不会写入问题，也不会丢弃已发生费用。崩溃留下进行中请求等待核对，不能自动假定未调用或重试；重新发起须人明确使用新请求。调用和等待不领取执行节点。

成功结果只接受严格`{"questions":[{"question":"...","context":"..."}]}`；写入与请求完成同事务，保存生成请求和相应charge关联。受影响版本已改变或批准时拒绝发布结果。可信代码负责结清失败状态，普通API/MCP不能伪造模型来源或完成生成。

规划模型与实际开发Worker共用选择器，读取当前批准需求的准确问答快照并验证摘要，作为业务数据；旧版本、其他项目和未回答内容不混入。损坏或只有摘要却缺失快照会阻塞；无快照且无摘要的旧批准兼容为空问答。答案不能授予工具权限或降低验收门槛。

## 工作台

使用`frontend-design`的现有设计系统模式，沿用浅色背景、绿色操作、现有字体、Form/Confirm和状态展示。在“需求基线”中按业务结果 → 验收标准/必选端 → 需求澄清 → 人工基线确认排列。问题按批展示来源与状态，当前问题可提问/回答/生成，历史折叠只读；未决数直接解释批准禁用。模型生成有明确费用提示、稳定请求key、进行中/失败反馈；表单支持Escape、焦点恢复、手机换行和键盘。

## 验证与边界

真实SQLite/PostgreSQL验证未决批准拒绝、不可覆写回答、并发回答/批准、当前权限、回放、版本隔离、审计回滚、备份恢复。HTTP/MCP验证角色、人类边界、CSRF/Origin、私有完成入口不开放。模型使用本机确定性HTTP提供方，验证草稿专用途径、策略/预算/撤权/变更、生成请求不重复调用、非法结果及规划上下文；不借此认定真实模型澄清质量。
