# 交付目标成本核算

本增量落实已批准产品规划的企业治理与“每次交付总成本”指标。沿用主线程执行、既有审批与权限，不进行付款、真实账单访问或生产操作。

## 当前问题与方案

费用页只有模型调用。采用既有资源模型增加不可覆写的非模型费用记录，并由服务端按项目或交付目标汇总。单纯在浏览器相加缺少一致性与 API；接入计费系统则依赖企业账户和价格配置，留待后续适配。

## 费用记录

`expenses.record` 只允许项目负责人中的人类身份。输入 goalId、title、category、amountCents、currency、incurredAt、reference、note、key；可选 proofArtifactId。类别为 build/device/storage/channel/labor/other，金额为 USD 整数美分 0–100000000；0 必须是明确的人工作业记录，不能由缺失推断。时间是有效 RFC3339，不接受超过当前五分钟的未来费用。引用是账单行、工单或分摊来源的稳定标识，说明必填。

记录固定目标和创建时需求版本、登记人、来源及可选报告附件的摘要。附件必须属于同一项目和目标，类型为 report；历史费用不因需求修订而消失。Agent/Worker/只读人员不能登记或作废。手工登记不代表独立账单认证。

同项目的活动费用来源 reference 唯一，即使换操作者、换目标或换幂等键也不能重复计入。`expenses.void` 用 id/key/reason 保留原金额与来源，记录作废人和原因，排除该行；无法原地改金额。作废后相同来源可重新登记，自动关联上一条作废记录。幂等回放不重复计费，换内容冲突。写入、幂等历史和审计同事务提交。

## 汇总与口径

`GET /api/v1/projects/{id}/costs?goalId=...` 对当前有权限的主体开放，goalId 可省略以汇总项目。事务内验证当前权限、项目/目标绑定，再读取一致快照。

- 模型费用分为按配置价格估算的已结算金额、人工核对的金额、预留/不确定待核对金额，后者不算已记录成本。
- 非模型费用仅统计 recorded 行，voided 历史可追溯。已记录小计是两类已结算模型金额加活动外部费用；包含待核对的风险敞口另列。
- build/device/storage/channel/labor 中无活动记录的类别显示“尚未记录”；other 是可选补充。
- 未知状态、旧数据中的非法/缺失金额明确列为无法核算记录，不能转为 0 或默默舍入。模型费用核对也收紧为整数美分。
- 始终注明这是当前登记口径，不宣称完整成本或已付款；不改变现有模型预算、调度准入、发布审批及验收状态。最终实际总成本仍需要完整企业账单与人工工时来源。

## 工作台

既有“企业治理”的费用页扩展为“交付成本”，跟随目标选择。展示已记录小计、待核对模型金额、模型预算和各类费用来源；提供登记、作废、原模型核对和作废历史。表单重试沿用同一 key。复用现有组件和视觉系统，支持手机换行、键盘与 Escape/焦点恢复。状态变化从服务端重新读取。

## 验证与边界

真实 SQLite/PostgreSQL 验证并发去重、幂等、作废/更正、当前权限和备份恢复；HTTP 验证匿名、CSRF、Agent 与跨项目拒绝及精确金额；Chrome 两种宽度完成实际 CRUD/核对与只读验收。外部费用与模型回执采用标注的合成账单数据，无付费模型、商店账户或外部计费请求。

保留原 18080/PID36063、web/dist、261 暂存条目、零提交、155 旧输出及原 Docker 资源。构建与验收使用独立工作目录。Apple/native/store 与完整 P3 仍保持开放。
