# 验收追溯设计

本增量补齐已批准产品规划中的目标追溯和需求覆盖验证。交付目标页新增“验收追溯”标签，通过只读报告呈现指定需求快照的验收标准与各必选端的准确制品、源码、构建来源、独立证据和发布状态。

报告通过事务内现行授权从已有记录派生，不增加持久化对象、质量例外或审批步骤。REST `GET /api/v1/projects/{projectId}/acceptance-trace?goalId=...&revision=...` 与 MCP `acceptance_trace` 共用服务。省略 revision 表示当前版本；显式版本必须为正整数且存在对应需求快照。

报告返回显式类型，禁止复制任意 run/task 数据。当前记录必须逐项重检包、报告、准确绑定及独立性。标准覆盖仅表示至少一个包具备与该标准匹配的独立证据；包的环境验证独立列出，完整发布条件由现有 releaseGate 复核，界面不将覆盖当成交付完成。

人工上传保留准确仓库和提交，但没有构建来源时明确显示；构建来源只能来自与包匹配的实际成功 run/task，方案及设计关联由该来源派生，不能套用当前方案。无附件的日志型验证明确显示。历史报告使用 requirement.Resource.Revision 选择快照，展示当前保存的 stale 状态，不恢复或推测旧通过状态，不计入当前覆盖。

发布区保留候选的实际状态、审批绑定与每个渠道状态；提审、等待审核、发布和验证分别展示。无候选时明确提示。需求或方案变化后重新读取，旧请求不能覆盖新目标或新版本。

采用测试先行验证错误绑定、篡改、历史隔离、权限撤销、REST/MCP、持久化恢复及桌面/移动行为。保留原预览及既有资源，不调用付费模型或真实发布接口。
