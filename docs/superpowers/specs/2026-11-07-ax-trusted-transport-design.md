# AX 固定身份与双向 TLS 执行设计

本增量落实已批准产品规划的控制面访问隔离、受控执行与可核对后端身份；不改变完整 P3 的验收标准。主线程执行，不暂存、提交、推送，不改变真实 AX/生产/商店环境，不调用付费模型，不代为接受 Apple 协议。

## 已发现的问题

原适配器运行 AX CLI，继承宿主环境。AX_SERVER、kubeconfig、AX_HOME 与包装程序可能改变控制面及客体路由；固定 context/namespace/atespace/image 的摘要不能认证后端。固定上游版本还允许客体直连、TLS 路由及明文回退。仅添加 server 参数不能同时保护两条连接。

## 选择

新增直接使用固定上游 protobuf 的受控 gRPC 路径。管理员配置两个 endpoint/TLS 身份：控制面网关和客体路由。两者都必须使用独立信任根、DNS 服务名、固定服务端 SPKI SHA256、客户端证书和私钥；TLS 至少 1.3，系统代理与 AX/Kubernetes 环境不参与。可共用管理员有意配置的证书。AX 服务本身未提供业务鉴权，控制面 endpoint 必须是企业认证网关，且原始 AX 端口只允许网关访问。

连接前读取并验证材料，保存内存快照；一次工具生命周期始终使用同一快照/连接，文件后续变化不能改道。只向平台发送 endpoint、服务名、CA 内容摘要、客户端叶证书 DER 摘要与服务端 SPKI 固定值。禁止发送私钥、文件路径和证书正文。不在程序中生成、续期或写入凭据，不使用系统钥匙串。

任务创建之前仍先写入 durable sandbox。准备接口支持原四字段后端及增加 transport 的后端；旧记录、审计、核对与备份可读取。新增路径不运行 CLI、kubectl 或外部认证插件；控制面 GetTask 必须返回准确资源名/atespace、Running/debug 与有效 Actor。客体请求只发往固定路由，附准确 ate-target-actor，不使用 WorkerIP。进程只有明确 exit 回执才能成功，缺失 exit、输出写失败、断流或上下文取消均失败。

所有成功仍依赖准确 Task/Workspace 删除和完整限定空间列表确认不存在。两项删除和两项列表都尝试；错误、无效作用域、空 metadata、残留或断连不能变为成功。拒绝新建连接时不发出创建请求；创建后不能确认清理则沿用 unresolved 屏障及人工 fencing。

无 secure 配置时默认拒绝执行。原 CLI 路径只能通过 allowLegacyCLI=true 显式启用，用于现有隔离诊断；它仍没有新增身份/隔离保证。secure 与该开关同时配置视为错误，绝不回退。示例采用 secure；旧示例需按手册迁移。

## 验证与明确边界

以真实 TLS/gRPC 服务、实际密钥协商和固定 protobuf 验证正常控制/客体命令、真实本地命令非零、双向认证、CA/主机名/SPKI/客户端身份错误、环境干扰、材料变化、取消、断流、部分创建、清理失败及准确持久记录。HTTP Worker、SQLite/PostgreSQL、双连接竞争、便携备份与独立读取验证原恢复门禁不退化。浏览器展示两条非敏感身份并保留原人工核对流程。

本地测试提供方不能证明真实企业网关按项目/操作授权、路由按 Actor 隔离、企业凭据撤销及时性、真实 Actor 停止或存储回收；这些仍需企业实测。两个 endpoint 的 TLS 身份绑定于管理员信任配置，不证明管理员配置正确，也不防受控节点本身失陷。私钥需私有普通文件且不能通过符号链接读取；证书信任与轮换由企业管理。真实多端构建、签名、设备、商店/生产发布与两应用正式交付仍开放。
