# AX 客体持久记录与中断恢复

此增量实现总体规划中的执行故障恢复和权限边界。现有 AX 驱动每次命令创建独占 Task/Workspace，但资源名只在内存中，Worker 失联后原任务能重新领取。进程退出的 defer 不是持久恢复证据。

## 决策与对象

控制面新增 `sandbox`，在任何 AX apply 前持久化，绑定 project/goal/task/run/worker、需求版本、原租约摘要、命令摘要、固定镜像和管理员配置的 context/namespace/atespace。控制面生成独占 ID 和 AX 资源名，不接收任意清理目标。记录不含凭据、源码或模型消息。

`sandboxes.prepare` 仅当前有权运行 Linux 工作项的可信 Worker 使用，原子检查当前方案、能力、租约、deadline 和既有未完成客体。同一 run/key 重试返回同一记录；重复响应不会授权再次执行，Worker 不重放 prepare 返回的既有记录。

`sandboxes.finish` 只记录原 Worker 对原记录的准确清理结果，可在原租约到期或需求取消后报告停止；不恢复任何执行权限。使用原租约摘要验证，原节点停用或凭据撤销后拒绝。状态为 `stopped` 或 `unresolved`，未确认清理不能产生成功工作项、源码或制品。原样回执幂等，冲突回执拒绝。

## 故障与人工核对

prepared/unresolved 客体阻止原 run 继续产生结果和同任务重试。同目标中失效或未明客体也阻止后续任务领取，避免换方案绕过。其他有效并行执行和其他目标保持可用。过期处理仍释放原预算和租约，但保留客体屏障。

负责人先停止或隔离原 Worker 并停用平台节点，在 AX 管理端检查准确 Task/Workspace 与下游 Actor。确认无活动租约后，通过 `sandboxes.reconcile` 提交准确资源名、backendDigest、幂等键和非空人工核对依据。它只关闭本记录、保留审计，不自动启动任务，不采用旧工具输出，不恢复旧租约。要求原 Worker 已停用，防止原进程随后继续使用其平台权限；其已持有的 AX 管理权限仍须由操作员在原环境撤销或隔离。平台无法独立证明人工核对事实。

## Worker 与 AX

Worker 的固定命令与 Agent run 动作使用同一受控执行入口。先 prepare，再以控制面生成的资源身份运行。重复 prepare、网络结果未明、finish 未确认都不重放命令。收到退出码后清理，成功的 Task 和 Workspace 列表都必须证实准确名称不存在；错误/空/不兼容列表不能算消失。清理失败将命令结果转为失败并报告 unresolved，清理诊断保留。

旧独立 AX 验证入口继续可用，但采用同一严格清理实现。此次不自动安装或改变真实 AX 集群，不接触生产凭据、原池或现有资源。不实现客体进程迁移、模型/工具会话恢复、输出复用或生产身份自动引导。

## 验收

真实 SQLite/PostgreSQL、HTTP Worker 与独立 CLI 进程验证：prepare 在 apply 前提交、正常完成、退出非零、部分创建、清理拒绝/保留对象/错误列表、进程终止后屏障、撤权、准确人工核对、并发幂等、回滚及便携恢复。真实 AX CLI 与本地 gRPC 服务验证列表和删除契约；受控模拟后端不算真实 Substrate 迁移或企业隔离验收。完整 Go race、受影响浏览器回归、源码/输出/环境保全和独立交付物读回后只关闭本增量，P3 仍需正式多端交付。
