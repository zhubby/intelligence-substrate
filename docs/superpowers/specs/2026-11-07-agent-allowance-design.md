# Agent 工作项跨重试累计配额

本增量落实已批准产品规划中的预算、时间和恢复边界。范围是没有固定 command、没有蓝图初始化器的 analysis/code/design 工作项。发布、签名、受保护质量与固定命令保留各自现有恢复语义。

一个批准工作项的 budgetCents、timeoutSeconds 和 24 次模型调用覆盖其所有执行，包括失败、租约过期、显式协作挂起和替代节点。新执行只领取剩余金额与活动时间。等待回复的时间不计入活动执行，失联执行计费到最后租约或原 deadline 中较早者；不能因为节点更换恢复整份配额。

任何关联该工作项的 reserved 或 uncertain 模型费用都会阻止重新领取和下一次模型请求。项目负责人通过原 charges.reconcile 核对后，仍按实际费用和原次数/时间限制继续；核对不退还调用次数，也不会自动运行任务。达到限制必须重新规划，通用 retry 不扩大授权。其他工作项的费用不污染该任务。

模型费用预留的 SQL 事务是调用次数的权威来源。一份请求记录即消耗一次，即使没有得到可用输出或随后人工核对为零费用。每次推理前检查当前需求、活动方案、节点能力、未过期租约、累计金额/活动时间/次数；不能通过直接调用模型 API、并发请求或事后上调旧费用绕过领取时的判断。预留前拒绝不会消耗次数或调用提供方。

领取的 run 保存 agentAllowance 快照：usedModelCalls、spentCents、activeSeconds、remainingCents、remainingSeconds。这是领取时快照，实时判断仍读事务数据。兼容已有 messageStepsUsed 和手工/旧版等待：调用步数取已知历史下界的最大值，每个新 run 的起始下界与其实际模型请求数累加，失败重试不能丢失该下界。既有配方哈希、等待和工作区绑定不增加可变计数字段。

恢复保留任务绑定的持久收件和既有确认工作区；不新增模型会话、工具结果或意外退出前文件的检查点，不自动重放工具，不声称消除外部副作用。无检查点的普通失败仍从原批准源码重启。此次本机确定性提供方仅验证协议和治理，不构成真实模型协作业务质量或 P3 正式交付。

验收覆盖真实 SQLite/HTTP/Worker，PostgreSQL 双连接争抢、原子回滚、费用核对竞争和备份恢复；独立读取数据库、审计与归档。完整 Go race 使用隔离 PostgreSQL 与 20 分钟超时；原预览、索引、已有输出、Docker、AVD 与 keychain 不变。禁止付费模型和实际渠道/生产动作，Apple 协议由用户本人处理。
