# Intelligence Substrate 产品规格

本规格落实用户已批准的企业智能研发与交付底座产品规划。

## 产品边界

- 服务企业内部研发团队，交付面向外部用户的新应用。
- 自有 Web 工作台，围绕项目与交付目标组织需求、计划、代码、质量、发布和审计。
- 一体化研发套件，内置 Git、评审、CI、制品和交付流程。
- Agent 动态规划、按需组队；需求基线、重大方案、正式发布由人审批。
- 企业内部署，按项目策略访问外部或内网模型。
- 必选端：Web、iOS、Android、Windows、macOS。
- 首批渠道：App Store、Google Play、华为、小米、OPPO、vivo，以及 Web 与桌面直接分发。
- AX/Substrate 是首选且可替换的 Linux 执行后端；原生平台使用独立执行节点。
- 资源与工期后定，按实际验收推进阶段。

## 六个子产品

1. 产品与需求：业务目标、需求版本、来源、验收标准、原型和变更。
2. Agent 协作：计划版本、任务依赖、角色、持久消息、预算、阻塞和恢复。
3. 开发环境：仓库、分支、代码浏览、变更、评审、合并和执行工作区。
4. 质量：独立执行、受保护测试策略、产物与版本绑定的验证证据。
5. 构建发布：不可变制品、发布候选、人工批准、渠道状态与发布验证。
6. 企业治理：身份、项目角色、凭据边界、审计、成本、备份恢复与运行可观测性。

## 权威状态与安全不变量

- 控制面持有权威状态；Agent 不能通过自由文本完成声明改变质量或发布结论。
- 需求、计划、代码提交、制品和审批绑定版本；变更使下游批准与证据失效。
- 开发者不能伪造独立自动化测试、真机或渠道验证。
- 每个操作检查项目成员身份、角色和主体类型；执行节点不自行选择权限。
- 所有必选目标验证通过才能交付。提审、等待、拒审、已发布、已验证分别记录。
- 持久消息至少一次投递、幂等处理、有限重试，异常外部结果进入待核对状态。
- 任务租约、重试、预算与截止时间由服务端执行，等待不占用执行节点。
- 签名凭据、商店账户和生产权限留在可信执行与发布服务。
- 代码仓库默认保护主分支，评审绑定源提交，源分支变化使旧评审失效。
- 密钥不进入计划、任务参数、审计或 Agent 上下文。

## 交付与验证

需求澄清 → 基线批准 → 方案与计划 → 重大方案批准 → 实现与候选构建 → 独立验证 → 发布批准 → 部署/提审 → 渠道验证 → 运行反馈。

移动端真机、桌面目标系统、真实浏览器与外部渠道必须有实际证据，不能用模拟结果代替。

## 建设阶段

- P0：对象模型、策略与执行可行性。
- P1：可信研发基础，手工项目经过平台构建、测试和追溯。
- P2：从业务目标到可验收多端应用的智能协作闭环。
- P3：两个不同业务应用完成全部声明必选渠道的真实正式交付。
- P4：更多蓝图、渠道、模型、容量与成本优化。

阶段标记依据证据；缺少集群、原生节点、模型、签名、设备或渠道账户时保持明确阻塞。
