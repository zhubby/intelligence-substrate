# 交付成本、费用来源与核对

在“企业治理 → 交付成本”按当前目标查看模型与外部费用。未选择目标时汇总项目，登记前须选择目标。金额以 USD 整数美分存储，页面输入 USD，保留两位小数。

## 口径

| 金额 | 来源与含义 |
|---|---|
| 模型估算 | settled 且未人工核对的 charge，按调用时配置价格计算 |
| 模型人工核对 | settled 且含 reconciledBy 的 charge，负责人填写核对依据 |
| 模型待核对 | reserved 的预留金额及 uncertain 的已保留金额，不算已记录小计 |
| 外部已登记 | recorded 的构建、设备、存储、渠道、人工和其他费用，为人工声明 |
| 已记录成本小计 | 模型估算 + 模型人工核对 + 外部已登记 |
| 含待核对金额的小计 | 已记录小计 + 模型待核对 |

小计始终保留不完整口径，不作为已付款或完整实际成本。类别无活动记录显示“尚未记录”，明确零费用须填写来源和说明。旧记录缺失/非法金额或未知状态显示“无法核算”，不转为0或舍入后计入。goal.spentCents 是模型预算缓存，不是第二份费用来源。

## 登记、作废与更正

1. 人类项目负责人选择目标，登记类别、金额、发生时间、稳定来源及依据；可选已上传的同目标 report 附件。
2. 同项目同来源的活动费用只能计入一次，换人、换目标或请求 key 不能重复登记。共享账单须先分摊成不同且稳定的来源标识，保留分摊依据。
3. 金额不能原地修改。先作废原记录并说明原因，再使用同来源登记正确金额。新记录关联最近的作废记录，原金额、操作者与原因保留。
4. 依据供应商记录核对模型待核对金额。核对更新原模型预算消耗；成功调用的配置估算不自动成为供应商账单。

外部费用不计入原模型预算准入，不授予发布/回滚或质量验收权限。需求修订不删除历史费用，也不将其绑定到新需求版本。Agent/Worker/只读和其他项目人员不能登记或作废。读取继承现有项目 RBAC，尚无独立财务保密域。

## API

`GET /api/v1/projects/{projectId}/costs?goalId={goalId}` 返回授权的一致快照，省略 goalId 汇总项目。包含 currency、generatedAt、complete:false、上述各项 *Cents、externalByCategory、unreportedCategories、unmeasurable、charges 和 expenses。金额不完整时先检查异常记录与缺失类别，接口不会依据已有记录自动宣布完整成本。

`POST /api/v1/commands/expenses.record`：

```json
{
  "goalId": "goal_...",
  "title": "Web 构建资源分摊",
  "category": "build",
  "amountCents": 1234,
  "currency": "USD",
  "incurredAt": "2026-11-06T06:00:00Z",
  "reference": "invoice-202611-line-001",
  "note": "已核对企业账单行和目标分摊依据",
  "key": "stable-request-key"
}
```

可选 proofArtifactId 须是同项目/目标的 report，保存附件 ID 与摘要。类别支持 build/device/storage/channel/labor/other。金额是显式数值，允许0–100000000整数美分，拒绝字符串、空值、小数和非有限数；currency 必须为 USD。时间为 RFC3339，未来偏差最多五分钟；工作台按浏览器本地时间转换并保留时区。

来源和 key 最长160字节，名称200字节，说明2000字节。同 key/内容回放已有对象，换内容409。活动来源唯一性跨项目内目标与操作者生效，作废后可重新登记；旧请求回放不会复活旧费用。

`POST /api/v1/commands/expenses.void` 使用 id/key/reason，reason 最长2000字节。同请求幂等；新 key 再次作废、改变幂等内容或重复活动来源返回409。认证、CSRF/Origin、当前角色与人类身份规则适用，非法金额/字段422。

`charges.reconcile {id,chargedCents,reason}` 沿用原待核对费用路径，金额同样要求显式且范围内的整数美分，不能用缺失或字符串隐式退款。

## 备份与验收

沿用[运行手册](operations.md)的一致备份及空目标恢复，expense/charge、作废更正、幂等与审计进入原控制面备份。附件正文沿用制品保留规则。两个 PostgreSQL 客户端并发竞争同一来源与实际归档恢复是必要验收，不能只凭单进程或空表备份判断。

本轮浏览器使用真实 API/SQL/身份权限及本机 HTTP503 模型测试服务。费用和供应商记录均为合成样本，没有付费模型、真实账单访问或付款。企业计费系统、基础设施/设备/存储自动用量、汇率/税费与人工工时来源后续接入，完整成本和效率收益仍须试点验证。
