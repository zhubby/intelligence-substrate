# 参考应用 B：服务预约

## 业务基线

外部用户查看开放时间、预约一个时段、保存不透明取消凭据，并用该凭据取消自己的预约。首版没有账号、支付、通知或日历同步。时间段由后端初始配置产生，数据存在 JSON 文件中，单实例运行。

## 验收

| ID | 行为 | 最低验证 |
|---|---|---|
| B1 | 可预约与已预约时段明确区分，预约后列表更新 | API + 各必选端业务流程 |
| B2 | 多个用户同时预约同一时段仅一个成功，其余得到冲突 | 并发自动化测试 |
| B3 | 预约返回不可预测凭据，服务端不保存凭据明文 | API/状态文件检查 |
| B4 | 错误凭据不能取消，正确凭据取消并重新开放时段 | API 自动化 + 客户端流程 |
| B5 | 预约/取消后服务重启保持正确状态 | 持久化重启测试 |
| B6 | 网络错误、重复点击和冲突有可见反馈 | 真实浏览器、移动真机与桌面系统 |
| B7 | 发布后的实际应用与批准包、API 版本匹配 | 各渠道独立发布验证 |

当前后端 race 测试覆盖并发唯一成功、取消授权及持久化。客户端会提示用户保存取消凭据；没有自动账号找回，丢失凭据需要人工处理，不声称拥有完整身份系统。

2026-11-06 已通过实际生成项目的 Flutter analyze、9 项 widget 测试与 Web release 构建。Chrome 使用真实 Go API 验证 B1、B3–B5，并用两个尚未刷新的客户端验证第二个预约收到实际 409 冲突；错误凭据不能取消，正确凭据取消后重启仍保持可预约。B2 的并发场景另由后端 race 测试覆盖。凭据在弹窗后仍保留于本次客户端输入框，状态文件仅保存摘要。桌面及 390px 浏览器截图和包摘要见 [验证记录](../validation.md)；真机、桌面目标系统和 B7 尚需独立验收。

## 交付声明

后续同制品验收已通过独立新应用的真实Worker构建与自动Chrome质量任务，预约冲突、取消授权、重启和离线恢复报告直接绑定平台准确package/提交/run，并形成待审批候选，见[质量报告](../reference-quality.md)。不借用反馈应用或早期外部包的证据；仍未公开发布。

Android arm64 调试包另在专用模拟器通过实际预约冲突、凭据保留、错误凭据拒绝、正确取消及服务重启持久性检查。该证据绑定本应用的实际 APK，不能代替真机或 B7 渠道验收。

完整参考交付的端与渠道与应用 A 相同，但使用独立应用 ID、目标、源提交、制品、证据和发布批准。不能复用 A 的业务测试结论或商店上线记录。正式生产仍需更换适合容量的数据库、监控、隐私/服务政策和运行恢复方案；这些未完成前，不将单实例示例 API 视作企业正式服务。
