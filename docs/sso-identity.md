# 企业 SSO 稳定身份与登录恢复

平台按企业已开通账户授予访问。OIDC 提供方证明员工身份，项目角色与人工审批权限继续由平台管理。

## 配置与首次登录

生产环境设置 `IS_PUBLIC_URL=https://...`、`IS_OIDC_ISSUER=https://...`、`IS_OIDC_CLIENT_ID` 和 `IS_OIDC_CLIENT_SECRET_FILE`。在提供方登记准确回调 `{IS_PUBLIC_URL}/auth/oidc/callback`，先由平台管理员创建对应企业邮箱身份。提供方、发现元数据、端点与证书信任须按企业配置验证。

生产必要端点及发现/交换/JWKS网络跳转必须保持完整安全的HTTPS URL；配置时的证书信任延续到普通回调。网络阶段有明确时限，降级失败不能复活已消费state。客户端信任、合法跳转和浏览器导航边界见[传输手册](oidc-transport.md)。

用户选择“使用企业单点登录”。平台创建十分钟有效、一次性使用的 state，发起带 nonce 与 S256 PKCE 的授权请求；回调验证令牌签名、issuer、audience、有效期、nonce 与已验证邮箱，再绑定稳定的 `issuer|subject`。主体须非空、非全空白，最多 255 字节，原始大小写和字节保持不变。

首次绑定使用已验证邮箱查找预先开通的账户。绑定后同一主体只能属于一个平台身份；不能因邮箱变化登录另一个账户。原账户停用后仍保留该绑定。停用不是将员工身份释放给新账户。

## 事务与并发

绑定在现有 SQL 事务中检查当前身份是否停用、原绑定是否一致，以及其他全部身份是否已占用相同主体，包括已停用身份。绑定和成功审计共同提交；失败事务保留原状态。两个独立连接竞争同一主体时，只允许一个身份成功。

如果历史数据已经将同一主体绑定到多个账户，两边登录都被拒绝，不自动选择或合并。应保留审计和备份，核对 IdP 的准确员工标识与原始账户，再通过经过审查的身份迁移或已验证恢复流程处理。主体转移与账户合并需要额外的受控迁移能力。

登录 state 的读取、时间解析、nonce/PKCE 结构验证和删除在带请求上下文的单个事务完成。以实际时间比较过期，拒绝非法时间和损坏记录；无效 state 不访问提供方。并发回调只消费一次。有效 state 在 token exchange 前删除，因此提供方失败后需要重新开始登录，原回调不能重发交换。

控制面重启会保留尚未消费且仍有效的 state；浏览器还需保有准确 state Cookie，提供方授权请求也需仍有效。成功或失败交换已消费的 state 不恢复。完成绑定后签发会话再次核对当前账户，避免停用与登录竞争复活会话。

## 权限、凭据与恢复

state、授权码、ID token、nonce、PKCE verifier 和会话值不进入登录审计。成功审计记录准确平台身份；角色不能由 OIDC 自报字段提升。

逻辑备份保留身份绑定与审计，排除 state、会话和委托 token；恢复后重新登录及签发凭据。原 IdP 凭据由企业独立恢复。唯一主体约束在恢复后的实际登录或绑定中重新检查。

平台仍提供本地密码登录。IdP 停用不会自动撤销已存在的平台会话；企业离职处理应同时执行平台账户停用。团队同步、SCIM、企业 MFA 与跨系统退出需要各自集成和验收，见[组织团队](organization-teams.md)与[成员及委托权限](memberships.md)。

## 验证与边界

```sh
rtk proxy go test -race ./internal/httpapi -run 'Test(OIDC|PostgresOIDC)' -count=1
```

PostgreSQL 测试需要隔离的 `IS_TEST_POSTGRES_URL`。`IS_SSO_IDENTITY_EVIDENCE_DIR` 可指定新目录，保留 SQLite/PostgreSQL 的实际备份、恢复数据库与并发事实，便于独立读取。未配置 PostgreSQL 的 skip 不计作数据库验收。

本轮使用本机签名 HTTPS OIDC 提供方与实际平台进程、真实 Chrome、桌面及 390px 视口。演练包含真实 SIGKILL、待回调登录跨重启、准确原身份/项目、旧回调不重复访问提供方及拒绝重复/空主体。私有测试 CA 不进入系统 keychain，浏览器证书放行仅在隔离测试上下文内。提供方不是实际企业 IdP；这些结果不证明生产 IdP、MFA 或企业离职流程已接通。

完整结果见[验收记录](validation.md)。原生端、真机、企业签名、商店和生产交付仍需实际证据，完整 P3 保持开放。
